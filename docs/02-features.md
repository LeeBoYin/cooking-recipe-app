# 02 功能規格

優先級標記：**P0** = MVP 必備、**P1** = 第二階段、**P2** = 之後再說、**🧪** = 實驗性，先做小規模驗證。

> **用詞**：自己寫的內容只有一種，叫「**食譜**」，動作是「**記錄**」（記錄一道菜＝發一篇）；把朋友的食譜或大廚的點子加進自己的「食譜」頁叫「**收藏**」；長時間的回顧叫「**回顧**」。

## 資訊架構（底部導覽列）

```
┌────────┬────────┬────────┬────────┬────────┐
│  首頁   │  食譜   │  ＋記錄  │  廚房   │  我的   │
│(朋友＋大廚)│        │ (大按鈕) │(食材+廚具)│(料理頁)  │
└────────┴────────┴────────┴────────┴────────┘
```

- **首頁**：像料理版的 Instagram 首頁，由上而下三個區塊（詳見下方「首頁」）：
  1. **和大廚聊聊**（最上方）：一個對話框，直接說今天想做的方向、心情、手邊有什麼，大廚邊聊邊給點子。下方緊貼著大廚主動給的最多 5 個點子，可以橫向滑動；資料不夠時誠實說明並鼓勵，不硬塞。
  2. **朋友的互動**：誰對你的食譜按了反應、留言、收藏了你的食譜、照你的食譜做了菜。
  3. **朋友的動態**：朋友最新記錄的食譜，文字在前、照片用小圖，可以按反應、留言、收藏。
  只有在設了期限的食材快到期時，才多一張小卡。**不放任何待辦事項**。畫面上不寫區塊標題，靠顏色與距離分出區塊（見 [17](17-visual-design.md#首頁)）。
- **食譜**：兩個分頁「我的食譜」（依月分組的時間軸）與「收藏」（朋友的食譜、大廚的點子、朋友送來的食譜），加上草稿與搜尋。
- **＋記錄**：中間的大按鈕。主要動作是「記錄一道菜」（發一篇）；按「記錄一道菜」直接打開編輯頁；也可以從網址匯入。食材只在「廚房」頁管理。
- **廚房**：頂端顯示目前所在的廚房（例：「我家」「爸媽家」），點一下可以切換廚房、查看成員、邀請家人。下方切換「食材」與「廚具」（不叫「冰箱」，因為很多食材不放冰箱）。
- **我的**：我的料理頁（朋友看到的樣子）、回顧（季節與年度回顧）、我的口味地圖、好友（好友清單、好友連結與 QR Code，加好友就從這裡）、設定。
**M0 的「我的」**（好友、料理頁、回顧、通知從 M2 起）：

| 項目 | 內容 |
|------|------|
| 頭像與暱稱 | 點頭像換大頭貼（見 H 節）；暱稱 1–20 字，預設「我」 |
| 我的口味地圖 | 看、改、重新探索、再多聊幾題（見 [13 第五節](13-taste-preferences.md#我的口味地圖偏好設定頁)） |
| 飲食限制 | 過敏、飲食原則、宗教與文化、不用料理酒、不吃的食物；和新手引導 ④ 同一個畫面 |
| 平常煮幾人份 | 1–20，記錄新食譜時預設帶入 |
| 最近刪除 | 全部「最近刪除」集中在這裡，一頁兩區：**食譜**（含草稿）與**目前所在廚房的食材**（區塊標題帶廚房名稱），保留期限內都能復原；兩區都沒有東西時只顯示一句話。食譜頁、廚房頁沒有各自的入口。**廚具不進這裡**：直接刪除，刪之前會在頁面內確認，並說明刪了不能復原 |
| 單位 | 溫度與度量（見 I 節） |
| 大廚的語氣 | 溫暖陪伴（預設）、熱血教練、冷笑話、簡潔；M0 沒有 AI，只影響情境文案挑哪一組 |
| 新手引導 | 還沒完成的步驟顯示一張溫和的小卡，可以關掉；也可以「重新跑一次新手引導」 |
| 帳號 | 顯示 email、登出 |

- **通知**：在「我的」裡面，收齊好友邀請、反應、留言、食譜被收藏等社群通知，以及設了期限的食材到期提醒。有新通知時，「我的」分頁出現紅點。

### 首頁

| 區塊 | 內容 | 空的時候 |
|------|------|---------|
| 和大廚聊聊 | 大廚的招呼語「叮！今仔日欲煮啥？」和一個對話框；開始打字就進入對話（見 E 節） | 永遠顯示；口味還不夠懂時，大廚會在對話中多問幾句 |
| 大廚的點子 | 對話框下方，大廚主動給的最多 5 個點子，一排橫向滑動 | 「再告訴我一點你的口味，或記錄幾道你做的菜，我就能給你更準的點子」＋繼續口味探索 |
| 朋友的互動 | 最新幾則：「小美對你的三杯雞按了 😋」「阿哲收藏了你的麻婆豆腐」「媽媽照你的食譜做了滷肉」；點進去是通知中心 | 不顯示這一區 |
| 朋友的動態 | 朋友最新記錄的食譜，依時間排列；每張卡片可以按反應、留言、收藏 | 有朋友但還沒分享 → 「朋友發第一篇時會出現在這裡」；沒有朋友 → 好友連結與 QR Code |
| 到期小卡 | 只有設了期限的食材快到期時出現 | 不顯示 |

- 動態只有朋友（與同廚房家人）的內容，沒有陌生人、沒有演算法推薦的熱門內容。
- 動態依時間排列，不做無限滾動的誘導設計；看完會出現「你已經看完朋友最近的分享了」。
- 新舊動態之間有一條細線「上次看到這裡」。位置記在手機上，只是畫面的位置，不是資料。
- 滑動中有朋友發了新食譜時，動態最上方浮出「有 2 篇新的」，點一下才載入，不會在你滑的時候自己跳動。
- 大廚偶爾在動態中插一句和朋友內容相關的點子：「小美記錄了韓式拌飯，你手邊剛好有材料。」

### 全站都不做的事

依產品原則「偶爾用也完整」，以下設計在任何頁面都不出現：

- 頻率與次數：本月下廚次數、連續天數、完成率、「你已經 N 天沒來了」
- 每日或每週的固定任務、有時間壓力的挑戰
- 補記提醒、日曆上的空格
- 食材的數量、用量、浪費統計、採購提醒
- 營養計算

## 核心概念：廚房與家人

> 產品從一開始就以「廚房」為單位設計。一個人住，就是自己一個人的廚房；和家人、室友同住，大家加入同一個廚房，共用食材和廚具，但食譜、口味、帳號仍然各自獨立。
>
> - **M0** 起：資料就屬於「廚房」。每個人自動有一個自己的廚房，單人使用時完全感覺不到差別。
> - **M2** 起：可以邀請家人加入廚房、共用食材，家人的修改即時出現在你的畫面。

### 什麼共用、什麼分開

| 共用（屬於廚房） | 說明 |
|-----------------|------|
| 食材（我們有的） | 全家有哪些食材。誰都能加、都能移除，並顯示是誰加的 |
| 廚具 | 同一套鍋具與電器，只屬於廚房，不分是誰的。成員搬走、帶走了某件廚具，由使用者自己在廚具清單更新 |
| 到期提醒 | 只針對設了期限的食材。每位成員都會收到；只要有一人處理，所有人的提醒就一起消失 |

> **廚房裡沒有食譜**：食譜永遠屬於寫的人。廚房頁的「家庭食譜本」只是一個檢視，把這個廚房的成員設成「🏠 家人」的食譜集中顯示（例：家傳食譜）；成員離開廚房，他的食譜也跟著他離開這個檢視。
>
> 「🏠 家人」＝和作者同屬**任一個**廚房的人。同時在「我家」和「爸媽家」的人，設成家人的食譜兩邊的家人都看得到。

| 分開（屬於個人） | 說明 |
|-----------------|------|
| 帳號、登入、AI 用量 | 每人一份 |
| 食譜、收藏 | 個人的；食譜想給家人看就把可見範圍設成「🏠 家人」 |
| 口味 | 每人不同 |
| 過敏原與不吃的食物 | 屬於個人，但加入廚房時會詢問是否讓家人知道（建議開啟，見下方「全家一起吃」） |
| 單位偏好 | 住美國的家人看華氏，你看攝氏，同一份食譜各自顯示 |
| 個人料理頁、好友 | 社群身分是個人的 |

### 加入與管理廚房

| 功能 | 階段 | 說明 |
|------|------|------|
| 自己的廚房 | M0 | 第一次使用時自動建立，可以改名（例：「我家」），你是它的管理者 |
| 廚房設定：時區與地區 | M0 | 建立時取手機的時區與地區，可以修改。到期日與「今天」以廚房的時區為準；季節、當季食材、節日料理依廚房的地區 |
| 邀請家人加入 | M2 | 輸入家人的 email，產生廚房邀請連結（或 QR Code）。家人還不是使用者也可以，**不需要管理者核准**：家人用連結建立帳號後直接加入廚房，並預設和你成為好友（計入使用人數上限）。家人已經是使用者的話，直接加入 |
| 讓家人加入（代碼） | M2 | 家人已經有帳號、人又在旁邊時用：在「廚房 → 成員」按「讓家人加入」，手機顯示一組 6 碼代碼（10 分鐘內有效、只能用一次）。不用輸入對方的 email |
| 加入家人的廚房 | M2 | 新手引導的「家人已經在用」，或之後在「廚房 → 切換廚房 → 加入家人的廚房」，輸入家人手機上的代碼。加入前先看到廚房名稱與成員，可以反悔；加入後廚房的成員都會收到通知 |
| 成員清單 | M2 | 顯示成員、角色（管理者／成員），以及沒有帳號的家人檔案 |
| 多個廚房 | M2 | 一個人可以屬於多個廚房（例：自己的租屋處、爸媽家），規則見下方 |
| 建立新廚房 | M2 | 在「廚房 → 切換廚房 → 建立新廚房」，輸入名稱就建立，時區與地區取手機的設定；你是它的管理者，建立後直接切換過去 |
| 離開廚房 | M2 | 自己的食譜跟著自己走；共用的食材與廚具留在廚房 |
| 合併食材 | M2 | 原本自己用的人加入家人的廚房時，可以選擇把自己廚房的食材與廚具搬進去，或保留成另一個廚房。自己的廚房是空的（新手時建立、還沒登記東西）就直接刪除，不用問 |
| 家人檔案 | M2 | 為沒有帳號的家人（小孩、長輩）建立檔案，見下方 |

### 角色與權限

每個廚房有兩種角色：**管理者**與**成員**。管理者可以有好幾位（例如爸媽都是管理者）。

| 動作 | 管理者 | 成員 |
|------|:----:|:----:|
| 看食材、廚具 | ✓ | ✓ |
| 新增、移除食材，標記想先用掉，設定期限 | ✓ | ✓ |
| 新增、修改廚具 | ✓ | ✓ |
| 修改廚房名稱、時區、地區 | ✓ | |
| 邀請家人加入廚房 | ✓ | ✓（不需要系統管理者核准） |
| 移除成員 | ✓ | |
| 指定或取消其他人的管理者身分 | ✓ | |
| 新增、修改家人檔案 | ✓ | |
| 刪除廚房 | ✓ | |
| 離開廚房 | ✓ | ✓ |

- **食材操作人人平等**：一起住的家人本來就互相信任。每個操作都記錄是誰做的，誤刪可以從「我的 → 最近刪除」復原。
- **角色不代表能看別人的私人資料**：管理者看不到成員的私人食譜或口味。家人的過敏原看不看得到，只取決於該成員自己有沒有選擇分享，和角色無關。廚房的管理者不是「家長監控」。
- 這裡的「管理者」是廚房的管理者，和 App 的系統管理員（管理後台）是兩回事。

### 多個廚房的規則

| 規則 | 說明 |
|------|------|
| 至少一個 | 每個人至少屬於一個廚房，因為要有「目前所在的廚房」 |
| 上限 | 每人最多 5 個廚房；每個廚房最多 10 位成員（不含家人檔案） |
| 切換跟著帳號走 | 「目前所在的廚房」記在帳號上，換手機也一樣 |
| 記錄食譜 | 記下是在哪個廚房做的 |
| 回顧 | 合併所有廚房的食譜 |
| 到期提醒 | 每個廚房可以分別開關。例如一個月只回去一次的爸媽家，可以關掉提醒 |

### 邊界情況

| 情況 | 做法 |
|------|------|
| 最後一位管理者要離開 | 必須先指定另一位成員當管理者 |
| 最後一位成員要離開 | 等同刪除廚房，要再次確認，並提供「把食材和廚具搬到我的其他廚房」 |
| 刪除帳號 | 比照離開廚房：最後一位管理者要先指定接手者；共用的食材、廚具、家人檔案留在廚房；個人資料與社群內容刪除 |
| 成員被移除 | 他的食譜跟著他走；他加的食材留在廚房，顯示為「前成員」加的 |
| 想刪掉自己唯一的廚房 | 不允許，至少要保留一個 |

### 家人檔案（沒有帳號的家人）

家裡常有不會自己用 App 的人，例如小孩或長輩，但他們的過敏原和喜好很重要。

- 管理者可以在廚房裡建立「家人檔案」：名字、過敏原、不吃的食物、飲食限制。不需要帳號，也不能登入。
- 「全家一起吃」時可以選他們，推薦會一併納入他們的限制。
- 家人檔案屬於廚房，同廚房的所有成員都看得到，因為大家都可能幫他們煮飯。
- 之後如果小孩長大、有了自己的帳號，用新帳號重新設定過敏原與飲食限制，再由管理者刪除原本的家人檔案（不自動轉換）。

### 全家一起吃

食譜與點子都可以選「這餐誰一起吃」，從同廚房的成員與家人檔案中選：

- **預設只有自己**：在對話中說「今晚全家吃」、或在點子上點「這餐誰一起吃」選人後才合併；同一段對話之後都沿用。每個人可以在廚房設定裡把自己的預設改成「全家」。
- **過敏原取聯集**：只要有一個人對花生過敏，就不推薦含花生的菜。這是硬性限制。
- **不吃的食物盡量避開**，口味找大家的交集。
- **份量**依人數自動調整。
- 成員若選擇不讓家人知道自己的過敏原，大廚推薦全家餐時會提醒：「有成員沒有分享飲食限制，煮之前記得問一下喔。」

### 讓家人一起更好玩（P1–P2）

| 點子 | 說明 |
|------|------|
| 今晚想吃什麼 | 大廚丟出三個選項讓全家投票 |
| 家的味道 | 標成「家人最愛」的食譜集中成「我們家的招牌菜」 |
| 家庭里程碑 | 「第一次全家一起做菜」「第一道家傳食譜數位化」，只有里程碑，沒有次數 |

## A. 食譜

> **記錄一道菜，就像發一篇貼文**：挑幾張好照片、寫幾句心得、標上為什麼值得記住；想留下做法，再寫食材和步驟。只記錄值得記住的料理；荷包蛋、炒青菜不用記，少記、很久沒記都完全沒關係。
>
> 「食譜」頁有兩個分頁：**我的食譜**（自己記錄的）與**收藏**（朋友的食譜、大廚的點子）。自己寫的叫「記錄」，把別人的加進來叫「收藏」。收藏不分「想做、做過、只是喜歡」，不用另外整理；做過的會自動標上「做過了」。

**使用情境**
- 第一次成功的戚風蛋糕，想好好留下來。
- 招待朋友的一桌菜，想記下菜色和當天的氣氛。
- 改良了好幾次終於成功的紅燒肉，想把做法寫下來，下次照著做。
- 翻車了，但過程太好笑，也想留下來。
- 在網路上看到一道菜，想存起來。

**兩種填法，用同一個編輯頁**

記錄一道菜的編輯頁一直是一般的欄位（標題、心得、食材、步驟、料理筆記…），自己打就能完成，不需要 AI。另外多一個「**用說的**」：按下編輯頁右下角的麥克風按鈕，用鍵盤的聽寫隨口講一段，大廚把它整理好、**自動填進同一頁的欄位**，使用者看過、改一改再發佈。做完菜很累的時候，只要拍照加說一段話，30 秒就能發出一篇有做法的食譜。

| 功能 | 優先級 | 說明 |
|------|-------|------|
| 用說的 | P1（M1b） | 編輯頁右下角浮動的 🎙 麥克風按鈕；第一次打開編輯頁時，大廚用一句話介紹它。按下後隨口講用了什麼、怎麼做、心得、踩到的雷（例：「培根先煎出油，再放高麗菜炒，加一點黑胡椒。培根太鹹了下次少放鹽。」）。用手機鍵盤內建的聽寫轉成文字，不錄音、不另外接語音服務 |
| 自動填入欄位 | P1（M1b） | 大廚把口述整理後填進：標題、心得（只修錯字、斷句與贅字，保留原本的說法）、食材（只寫說出口的份量，沒說的寫「適量」）、步驟（通常 3–4 步）、料理筆記（從口述中挑出提醒與防雷）、值得記住的原因、難易度。**不看照片**：照片裡有、但沒說出口的食材不會自動加 |
| 發佈前可以改 | P1（M1b） | 填好的就是一般的編輯頁，每個欄位都能改，看過再按「發佈」。已經自己填過的欄位，大廚不會覆蓋，只補空的欄位 |
| 不標示 AI | P1（M1b） | 朋友看到的食譜不標「AI 整理」；內容由作者自己檢查 |
| 保留原話 | P1（M1b） | 口述的原文只有作者看得到，之後想讓大廚重新整理時以它為準 |
| AI 不能用時 | P1（M1b） | 預算用完或出錯時，原話先放進心得欄位，可以照樣發佈；之後在編輯頁按「讓大廚整理」再填一次 |
| 再跟大廚說（用說的改食譜） | P1（M1b） | 發佈前在編輯頁、發佈後在食譜頁，都用同一個麥克風按鈕對大廚說：「把蒜頭拿掉，XO 醬改成兩大匙」「步驟二改成先燙過」。大廚列出會改哪些地方，作者確認後才套用；已發佈的食譜改了做法會留下版本 |
| 從留言補做法 | P2 | 朋友留言問「XO 醬放多少？」，作者回覆後，大廚問一句「要把這個寫進做法嗎？」，確認後更新 |
| 整理以前的貼文 | P2 | M0、M1a 期間只有照片和心得的食譜，可以一鍵「讓大廚整理」，從心得的文字補出做法 |

**記錄**

| 功能 | 優先級 | 說明 |
|------|-------|------|
| 記錄一道菜 | P0 | 按「＋記錄 → 記錄一道菜」直接打開編輯頁，不先選照片。照片（最多 5 張，從相簿挑或現拍，拖曳排序，第一張就是封面）、標題、心得與故事。**有照片和菜名才能發佈**（草稿不受限制，缺的先補上再發佈）；食材每一列、步驟每一步都能刪除，也能用左邊的把手上下拖拉排序（手機按住把手拖，鍵盤也能操作），存檔時順序照畫面 |
| 做法（選填） | P0 | 份量、食材清單、步驟（每步可附照片）、料理筆記（心得以外的提醒與防雷，例：「培根很鹹，下次少放鹽」）。不填烹煮時間。現在不寫也沒關係，之後隨時補；沒有做法的食譜也是完整的一篇 |
| 食材以自由文字輸入 | P0 | 打「醬油 2 大匙」即可，一列一個文字框。存檔時程式把每一列解析成「食材＋數量＋單位」（例「蒜 2–3 瓣」「鹽 適量」），份量換算、單位切換、「列出要買的」、「廚房有」都用解析結果；解析不出來也沒關係，就照原文顯示。畫面上不顯示解析結果。對不到字典的食材（例：「阿嬤的辣醬」）可以選填「含哪些過敏原」；沒填時，有過敏的人看這道菜會看到「有 1 樣食材無法確認成分」 |
| 草稿 | P0 | 編輯頁有內容就自動存成草稿，不用另外按；按「發佈」才公開。草稿只有自己看得到，也**不會提醒你補完**；「我的食譜」最上方一列「草稿 2 篇 ›」，不混進時間軸。草稿的文字與照片都在每次有改動後存到雲端；M0 不另外在手機暫存沒存到的文字 |
| 值得記住的原因 | P0 | 固定的七個選項，可多選、選填：第一次做、招待朋友、改良成功、家人最愛、節日料理、值得再做、翻車也好笑。不能自訂；之後如果加了新選項，舊版 App 遇到不認得的代碼就略過不顯示，不報錯 |
| 難易度 | P0（自動估 M1b） | 一個 1–10 的分數，取代烹煮時間與要洗幾件（因人而異，給數字反而不準）。由五個面向算出：食材、廚具、時間、技巧、失敗風險；點進食譜用雷達圖顯示各面向的強度。M0 的編輯頁不放難易度；M1b 起由 AI 自動估（大廚發想的食譜也會帶），作者可以調整，已有難易度的食譜照常顯示。算法見 [03 難易度](03-ai-design.md#難易度) |
| 可見範圍 | P0 | 🔒 只有自己／🏠 家人／👥 好友，**預設好友**；發佈按鈕旁清楚顯示「好友」（選項：家人、好友、自己；標題「誰看得到」），一鍵就能改。M0、M1 還沒有社群功能時，選好友等於只有自己看得到 |
| 隨時編輯 | P0 | 照片、文字、做法隨時可以改，像修改一篇貼文。草稿自動存；**已發佈的按「儲存」才更新，連照片也是**，朋友在按下之前看到的還是原本的樣子；改了還沒儲存就要離開時會問一次。兩個地方同時改時，App 自動用最新版重送，畫面上不處理衝突 |
| 又做了一次 | P1 | 在自己的食譜按「又做了一次」，留下日期、照片和一句話（「這次少放糖，更好吃」），可以順手改做法。不顯示「做過幾次」 |
| 一起吃的人 | P1 | 同廚房的家人、家人檔案、朋友，或自己打的名字。**只有作者看得到**：用來合併一起吃的人的過敏原，以及宴客時提醒「上次請小美吃過這道了」；不標記、不通知朋友 |
| AI 補標籤 | P1 | 從標題、心得與做法的**文字**推測菜系、主要食材、手法、廚具；不看照片；使用者可修正 |
| 從網址匯入 | P1 | 貼網址，AI 擷取標題、食材、步驟，保留來源連結（僅供個人使用）；預設只有自己 |
| 食譜版本 | P1 | 每次修改做法留下版本，看得到「我的紅燒肉 v1 → v4」怎麼演化 |
| 記錄時大廚的一句話 | P1（M1b） | 按下發佈時，大廚偶爾回一句這道菜的觀察：「薑放得這麼大方，冷天喝這碗剛好。」只根據這一篇，不提次數；只在發佈時出現，不定期寄送 |

**瀏覽與使用**

| 功能 | 優先級 | 說明 |
|------|-------|------|
| 時間軸 | P0 | 「我的食譜」只有時間軸，不提供其他排序：依記錄的日期由新到舊、**依月分組**（標題「11 月」，不是今年的寫「2025 年 12 月」），卡片上不放日期。照片為主，**只顯示有記錄的月份**，沒有日曆、沒有空格；「又做了一次」的日子也會出現一張卡，顯示那次的照片與一句話，不顯示做過幾次 |
| 搜尋 | P0 | 依名稱、食材關鍵字搜尋，不含心得；結果同樣依月分組，標出是名稱還是食材符合。沒有篩選鈕（M0 用簡單的比對，不上全文索引） |
| 收藏 | P0（大廚的點子 M0、朋友的食譜 M2） | 朋友的食譜和大廚的點子都可以收藏（見 [M 節](#m-料理社群)、E 節）。不提供篩選：朋友的食譜與大廚的點子混在同一條依收藏月分組的時間軸，靠卡片上的來源（朋友的頭像與名字、大廚的燈泡）與「做過了」「還沒做過」標籤分辨。「做過了」是自動的：從收藏記錄了自己的版本，就會標上。還沒做過的收藏材料差不多齊時，大廚會在首頁提一句 |
| 列出要買的 | P0 | 食譜頁列出這道菜的食材，讓使用者勾要買的，再複製或分享到提醒 App（見下方） |
| 烹飪模式 | P1 | 大字一步一頁、螢幕常亮、多組計時器、語音說「下一步」（實驗）；做完可以直接「記錄這一次」 |
| 份量與換算 | P0 | 食譜記下「幾人份」，記錄時預設帶入平常煮的人數。食譜頁顯示「2 人份 ▾」，切換人數時食材數量跟著換算（2 人份 → 4 人份就加倍）；「適量」與沒寫數量的不換算 |
| 改成我的版本 | P1 | 以自己或朋友的食譜為基礎複製一份，自由修改，保留「改編自」的來源 |

**列出要買的：送到提醒 App 前先確認**（P0）

App 記錄的食材不一定完整：沒有記在「食材」裡，不代表家裡沒有。所以食譜頁只標「廚房有」，**不標「缺」**，也不讓人覺得有義務把食材記完整。

1. 在食譜頁按「列出要買的」，跳出清單，列出這道菜的**所有食材**；份量依目前選的人數。
2. 廚房有的標「廚房有」、不勾；其他的先幫你勾好。使用者自己增減。
3. 按「複製清單」或「分享到…」（手機的分享選單，例：iPhone 的提醒事項、Google Keep、Todoist、LINE）。送出的只有勾選的項目，一行一樣，可以直接變成待辦事項。

這裡不會改到食材清單；食材只在「廚房」頁管理。App 本身不做購物清單。

## C. 食材（手邊有的）

> 食材清單是**靈感素材庫**，不是庫存帳。只記「有沒有」，不記數量、不追蹤用量、不提醒採購。

**使用情境**
- 買菜回來，隨手把幾樣東西加進去。
- 想煮點什麼時，看看手邊有什麼可以用。
- 想記得櫃子裡有哪些醬料，讓大廚幫忙想怎麼用。
- 不常用、容易忘記的調味料，記下期限免得放到過期。

**分區與標記**

| 分區 | 範例 |
|------|------|
| 🧂 調味料與醬料 | 醬油、沙茶醬、豆瓣醬、味醂、XO 醬 |
| ❄️ 冷藏 | 蔬菜、豆腐、雞蛋、肉 |
| 🧊 冷凍 | 冷凍肉、水餃、高湯塊 |
| 🥫 常溫乾貨 | 米、麵、罐頭、乾香菇 |

| 標記 | 怎麼來 | 用途 |
|------|-------|------|
| 🔥 想先用掉 | 使用者手動 | 大廚優先用它出點子 |
| ⏰ 有期限 | 使用者設定了有效期限 | 到期前提醒（見下方） |

**功能**

| 功能 | 優先級 | 說明 |
|------|-------|------|
| 快速新增 | P0 | 打字搜尋（內建食材字典）、常買清單。點了就在下方多一張**食材卡**，卡片上可以設定放哪裡、想先用掉、選填的期限，也可以移除；看完所有卡片，按最下方的「加入 N 樣食材」才真的加入。只記「有」，不記數量。常買清單自動產生：依這個廚房過去 30 天加入過的食材排序（已移除的也算），次數只用來排序、不顯示；新廚房先用地區的常見食材清單 |
| 快速盤點 | P0 | 常見食材的圖示牆，點一下「有」、再點一下「沒有」，30 秒更新食材 |
| 移除 | P0 | 「用完了／不在了」一鍵拿掉，不問原因。誤刪可以從「我的 → 最近刪除」復原 |
| 想先用掉 | P0 | 一鍵標記，大廚優先用它 |
| 有效期限（選填） | P0 | 放在新增或編輯畫面的「更多選項」裡，屬於次要層級。欄位旁說明「設定期限的食材，到期前會提醒你」。詳見下方 |
| 還在嗎？ | P1 | 生鮮加入很久時，大廚在食材頁輕輕問一句「高麗菜還在嗎？」，一鍵移除或保留。不推播、不追問原因 |
| 語音新增 | P1 | 「雞蛋、青江菜、豆腐」一次說完。不做拍照辨識食材與廚具（和「AI 不看料理照片」一致） |
| 拍收據／發票 | 🧪 P2 | 辨識超市收據品項 |
| 共用食材 | M2 | 食材屬於廚房，同廚房的家人一起維護（見上方「核心概念：廚房與家人」） |

### 有效期限（選填）與到期提醒

只有使用者**自己設定了期限**的食材才會提醒。最適合不常用、容易忘記的調味料與乾貨，例如魚露、味醂、泡打粉。

**設定期限**

| 項目 | 說明 |
|------|------|
| 位置 | 新增或編輯食材時的「更多選項」，不佔主要畫面 |
| 兩種日期 | **有效日期**：包裝上標示，過了就不建議食用。**賞味期限**：過了品質下降，不一定不能吃 |
| 快速輸入 | 快捷按鈕：+1 週、+1 個月、+3 個月、+半年、自選日期。拍包裝上的日期辨識列為 🧪 P2 |
| 不做 | 系統自動估算期限、開封後重算、冷凍重算 |

**提醒分級：依效期長度按比例**

效期 1 週和效期 2 年的東西，不能都用「剩 3 天」來提醒。提醒時機依「總效期」（到期日 − 設定期限的那天）按比例計算，再加上下限與上限：

| 狀態 | 條件 | 呈現方式 |
|------|------|---------|
| 🟡 盡快使用 | 剩餘天數 ≤ 總效期的 **25%**（最少 1 天、最多 30 天） | 食材頁標示；大廚出點子時優先用它 |
| 🟠 即將到期 | 剩餘天數 ≤ 總效期的 **10%**（最少 0 天，即到期當天；最多 7 天） | 首頁出現一張小卡；列入到期提醒 |
| 🔴 已過有效日期 | 日期類型是「有效日期」，且已過期 | 列入到期提醒，不再出現在任何點子中，直到使用者處理 |
| ⚪ 已過賞味期限 | 日期類型是「賞味期限」，且已過期 | 「看看狀況再決定喔」，由使用者判斷 |

- **通知**：🟡 只在剛進入時通知一次；🟠、🔴、⚪ 當天彙整成一則，時間可設定（預設傍晚 5 點），可以整個關閉。沒有設期限的食材永遠不會出現在提醒裡。
- **提醒卡的動作**：✅ 用完了（移除）、🍳 幫我想怎麼用、📅 修改日期、🗑️ 移除。不記錄原因、不做浪費統計。

## D. 廚具

> 就像遊戲裡的裝備欄。有些人對自己的鑄鐵鍋、主廚刀、舒肥機如數家珍，這裡讓他們好好展示。同時，AI 知道你有哪些器具，就知道你能用哪些手法，給的點子才能更靈活、更有創意。

廚具屬於廚房：同廚房的家人共用同一份廚具清單，推薦時依「目前所在廚房」的廚具判斷做不做得到。

**不計算使用次數**：廚具不記出場次數、冷落天數，不會讓人有「買了沒用」的壓力。大廚只用正向的方式提起它們（在首頁的靈感彩蛋與對話中）：「你有舒肥機，這個週末要不要試試舒肥牛排？」**廚具頁本身不放大廚的點子**：剛開始用時大部分廚具都還沒出現在食譜裡，在廚具頁提起會變成壓力。

**使用情境**
- 剛開始用 App，想快速告訴它「我家有電鍋、氣炸鍋、烤箱」。
- 我很愛我的鑄鐵鍋，想記下它的故事、用它做過的拿手菜。
- 舒肥機買了還不太會用，想知道能拿它做什麼。
- 想買新器具，但不確定是不是真的需要。

**器具分類**

| 分類 | 範例 |
|------|------|
| 🍳 鍋具 | 炒鍋、平底鍋、鑄鐵鍋、琺瑯鑄鐵鍋、湯鍋、雪平鍋、砂鍋、蒸籠、壓力鍋 |
| 🔌 廚房電器 | 電鍋、氣炸鍋、烤箱、微波爐、電烤盤、電磁爐、舒肥機、麵包機、慢燉鍋、洗碗機 |
| 🌀 攪拌與打碎 | 調理機、果汁機、食物處理機、手持攪拌棒、桌上型攪拌機、電動打蛋器、研磨缽 |
| 🔪 刀具與備料 | 主廚刀、中式菜刀、刨絲器、削皮刀、蒜泥器、擀麵棍、廚房剪刀 |
| 🔥 特殊工具 | 噴槍、煙燻槍、卡式爐、真空封口機、製冰盒 |
| 📏 量測 | 料理秤、溫度計、量杯量匙、計時器 |
| 🧁 烘焙 | 烤模、擠花袋、刮刀、網架 |

**功能**

| 功能 | 優先級 | 說明 |
|------|-------|------|
| 新手盤點 | P0 | 第一次使用時，用圖示牆勾選「你的廚房有什麼」（48 種常見廚具，其中 10 種大部分家庭都有的預設已勾選），30 秒完成 |
| 新增／編輯器具 | P0 | 從內建器具字典選，或自訂名稱；選填品牌型號、容量尺寸（如 10 人份電鍋、5 公升氣炸鍋）、照片、入手日、自由填寫的描述。所有廚具都視為可以使用，不設狀態 |
| 能力自動帶入 | P0 | 選了「氣炸鍋」，系統就知道它能氣炸、烤、烘乾，**使用者不用、也不能改手法**。手法完全由類型決定：鍋具是煮燉炒，刀子是刨絲切片，濾網、量杯這類工具沒有手法。類型有選配功能時才問一句（例：烤箱「有熱風功能嗎？」）。字典沒有的自訂廚具只記名稱，不參與推薦 |
| 裝備卡 | P1 | 每件器具一張卡：照片、入手日、能做的手法、拿手菜（記錄裡用到它的食譜）、描述 |
| 廚具靈感 | P1 | 大廚偶爾用你的廚具給點子，例如還沒出現在你食譜裡的手法：「你有噴槍，要不要試試炙燒鮭魚？」 |
| 裝備圖鑑 | P2 | 像集郵冊的圖鑑檢視；還沒登記的常見器具顯示成剪影 |
| 購買前諮詢 | 🧪 P2 | 「想買舒肥機？」大廚告訴你現有器具已經能做到哪些、新器具能解鎖哪些料理。想清楚再買，也是一種不浪費 |
| 分享我的廚房 | P2 | 產生廚房的廚具圖卡，和同好互相炫耀（個人料理頁不放廚具） |

**廚具 → 手法**

每件廚具在字典裡都對應到它能做的「手法」（煎、煮、炒、炸、蒸、烤、微波、舒肥、打碎、冷凍、發酵等 32 種）。AI 和不用 AI 的推薦都靠這張對照表判斷「你能怎麼煮」。少了某件廚具時，字典也記錄了替代做法，例如沒有氣炸鍋可以用烤箱熱風模式，推薦不會因為缺一件廚具就放棄一道菜。

完整的手法、68 種廚具、替代做法、安全規則與清洗標記，見 [07 廚具與手法字典](07-equipment-techniques.md)。AI 怎麼用這些資訊給更有創意的點子，見 [03 AI 設計：器具與手法](03-ai-design.md#器具與手法讓點子更有創意)。

## I. 單位與換算（共通設定）

台灣習慣攝氏、公克、毫升，美國用華氏、杯、盎司。家人分住兩地，或照著美國食譜做菜時，都需要切換。介面語言仍然只有繁體中文，單位偏好和語言分開設定。

**使用者偏好**

| 設定 | 選項 | 預設 | 優先級 |
|------|------|------|-------|
| 溫度 | 攝氏／華氏／攝氏（華氏）／華氏（攝氏） | 攝氏 | P0 |
| 重量與容量 | 公制／美制／公制（美制）／美制（公制） | 公制 | P0 |

- 括號表示兩種都顯示，括號內是次要單位，例如「180°C（355°F）」、「1 杯（240 毫升）」。
- 偏好存在帳號裡，換手機也一樣。每位家人用自己的帳號，各自設定。
- 食譜頁和烹飪模式有一鍵切換，只影響這次瀏覽、不改設定，適合偶爾照著美國食譜做菜的時候。

**換算範圍**

| 類別 | 公制 | 美制 | 台灣常用 |
|------|------|------|---------|
| 溫度 | °C | °F | |
| 重量 | 克、公斤 | 盎司 oz、磅 lb | 台斤（600 克）、兩（37.5 克） |
| 容量 | 毫升、公升 | 茶匙 tsp、大匙 tbsp、杯 cup、液量盎司 fl oz、夸脫 qt | 大匙、小匙、量杯、米杯 |
| 尺寸（模具、鍋子） | 公分 | 英吋 | 吋（「6 吋蛋糕模」） |
| 廚具容量 | 公升 | 夸脫 qt | 人份（電鍋） |

**換算規則**

1. **存原始值，顯示時才換算**：使用者輸入「350°F」就存 350°F，不先轉成攝氏再存，避免來回換算產生誤差（350°F → 177°C → 351°F）。
2. **合理進位**：
   - 烤箱溫度：攝氏進位到 5°C、華氏進位到 5°F，對應烤箱刻度。例：180°C 顯示為 355°F。
   - 份量：美制用常見分數（¼、⅓、½ 杯），公制進位到合理精度（一般到 5 克／5 毫升，少量時到 0.5）。
3. **安全溫度不粗略進位**：AI 推薦用到的中心溫度、舒肥水溫這類安全相關的溫度表，直接存資料來源公布的攝氏與華氏數值，不經換算。使用者自己寫的食譜不特別處理安全溫度，溫度照一般規則換算。
4. **「杯」容易混淆，要分清楚**：
   - 美制 1 杯約 237 毫升，台灣量杯常見 240 毫升，差距不到 2%，視為同一種。
   - 米杯約 180 毫升，差很多。電鍋步驟裡的「外鍋 1 杯水」預設是米杯。
   - 日本食譜的 1 杯是 200 毫升，從日文網站匯入時要特別標記。
5. **大匙、小匙**：視同美制的 tbsp、tsp（15、5 毫升）。
6. **台斤、兩**：一律附上公制，例如「半斤（300 克）」。中國大陸的「斤」是 500 克，從簡體中文網站匯入時要請使用者確認。
7. **重量和容量不互換（P2 才做）**：「1 杯麵粉」換成克，要看食材密度，麵粉、糖、米都不一樣。食材字典有密度資料時才換算，並標示「約」；沒有就維持原單位。
8. **步驟文字裡的數字也要能換算（P1）**：「烤箱預熱 180 度」這類寫在步驟文字裡的溫度與份量，輸入或匯入時由系統辨識，轉成可換算的標記。台灣食譜寫「度」視為攝氏，從英文網站匯入時視為華氏，不確定時請使用者確認。
9. **分享**：
   - 公開分享頁依瀏覽器語系決定預設單位（英文、美國地區 → 華氏與美制），頁面上可以切換。
   - 食譜圖卡預設依分享者的設定，也可以選擇兩種都顯示。

## J. 外部 AI 連接器（MCP）

> 排在 M4。

讓使用者用**自己的 AI**（例如 claude.ai、Claude Desktop 等支援 MCP 的 AI 工具）讀寫 App 裡的資料。使用者在自己的 AI 裡加入「今仔日煮啥」連接器並登入授權，就能直接問：

- 「看看我手邊的食材，今晚煮什麼？」
- 「我今年記錄的食譜裡，哪幾道最適合拿來招待朋友？」
- 「把剛剛那道菜記錄成食譜。」
- 「豆腐用完了，幫我從食材拿掉。」

AI 的費用由使用者自己的 AI 服務負擔，不計入 App 的 AI 用量。App 內建的大廚功能照常運作，連接器是給想深入對話的人的額外選項。

**開放的功能**

| 類別 | 工具 | 說明 |
|------|------|------|
| 讀取 | 查詢食材 | 食材有哪些食材，以及「想先用掉」；設了期限且已過有效日期的另外列出，並標示「不可推薦」 |
| 讀取 | 查詢食譜 | 搜尋、讀取我的食譜（可指定期間或「值得記住的原因」）與收藏 |
| 讀取 | 口味檔案 | 口味摘要（和 App 內 AI 用的同一份） |
| 讀取 | 廚具 | 可用的廚具與做得到的手法 |
| 讀取 | 我的限制 | 過敏原、不吃的食材、飲食限制、單位偏好。工具說明會要求 AI 推薦前先讀這一項 |
| 讀取 | 安全參考 | 中心溫度參考表、舒肥預設組合表 |
| 寫入 | 記錄食譜 | 新增食譜（文字部分；照片之後在 App 補），預設只有自己，來源標示「來自你的 AI」 |
| 寫入 | 更新食材 | 新增、移除食材，標記想先用掉 |
| 寫入 | 加入收藏 | 收藏外部 AI 想出的點子 |

**刻意不開放的**：刪除任何資料、建立或撤銷分享連結、帳號與設定、照片（第一版只開放文字資料，減少資料外流的範圍）。

**授權與控制**

| 項目 | 說明 |
|------|------|
| 登入授權 | 第一次連接時，在 App 的授權頁登入並同意，清楚列出對方能讀、能寫哪些資料 |
| 權限分級 | 「只能讀取」與「讀取＋寫入」分開授權，預設只能讀取 |
| 多個廚房 | 預設讀寫目前所在的廚房，工具可以指定廚房；寫入時回報寫到哪個廚房 |
| 管理 | 「我的 → 已連接的 AI」列出所有連接，顯示最後使用時間，可以隨時中斷 |
| 標示 | 透過連接器寫入的資料，在 App 中標示「來自你的 AI」 |

**安全**

使用者的 AI 不會經過 App 的過敏原與安全檢查，所以：

- 讀取工具回傳的資料就附上限制（過敏原清單、已過期不可推薦、舒肥只能用預設組合）。
- 寫入的食譜由後端檢查：含過敏原、或舒肥溫度時間不在預設組合表內，仍會儲存，但在 App 中加上醒目的警告。

**優先級**：P2（M4）。免費方案也能用：它用的是使用者自己的 AI，App 不負擔 AI 費用，只設呼叫頻率限制（依產品原則 10「只為成本收費」）。

## K. 帳號與邀請制註冊

> 初期只開放受邀的人註冊，**使用人數上限 30 人**。後台與 App 用**同一個邀請表單**，多一個勾選「也邀請他加入我的廚房（給同住的家人）」：勾了是**廚房邀請**，受邀者註冊後直接確認加入邀請者的廚房；沒勾是**一般邀請**，受邀者建立自己的廚房。使用者發廚房邀請不需要你核准。資料都存在雲端，所以**所有功能都要登入受邀的帳號**。M0 只有你自己的帳號；M1 開始邀請親友。
>
> **App 不寄任何信**：邀請連結由你在管理後台產生，自己用 LINE、Messenger 或自己的信箱傳給對方。M1、M2 都不需要寄信服務和寄件網域。

**產生邀請連結（管理後台）**

1. 輸入對方的 email、備註（例：「小美，大學同學」）、方案（免費／進階）。勾選「也邀請他加入我的廚房」時，對方註冊後直接確認加入你的廚房；沒勾時，對方建立自己的廚房。預設和你成為好友（可取消勾選）。
2. 按「產生邀請連結」，畫面顯示：
   - 邀請連結，旁邊有「複製」按鈕。
   - 一段可以直接貼上的邀請訊息（大廚語氣，已包含連結）。
   - 「分享」按鈕：叫出手機的分享選單，直接傳到 LINE 等 App。
   - 「用我的信箱寄」按鈕：打開你自己的郵件 App，收件人、主旨、內容都已填好，你按送出就好。
   - QR Code：當面掃描用。
3. 你把連結傳給對方。

邀請訊息範本：

> 叮！我邀請你一起用「今仔日煮啥」。
> 這是朋友之間的料理社群，看看大家做了什麼好菜，還有懂你口味的靈感大廚幫你想點子。點這個連結就能開始，14 天內有效：
> （邀請連結）

**連結只會顯示這一次**：資料庫只存連結的雜湊值，之後無法再顯示原本的連結。如果忘了複製或對方弄丟了，在邀請清單按「重新產生連結」，舊連結會同時失效。

**iPhone 用邀請碼接續**：受邀者在 Safari 打開連結後，新手引導先教安裝到主畫面，並顯示一組 6 碼邀請碼（1 小時內有效）；從主畫面打開 App 時輸入，就能接著註冊，只要登入一次（見 [12 新手引導](12-onboarding.md)）。

**使用者邀請家人（M2）**

- 在「廚房 → 成員 → 邀請家人」用同一個表單，「也邀請他加入我的廚房」預設勾好；輸入家人的 email，產生連結，分享方式和後台相同（複製、分享、當面給對方掃 QR Code）。
- 家人還不是使用者：點連結建立帳號，新手引導中只要確認加入這個廚房，並預設和邀請者成為好友。
- 家人已經是使用者：邀請直接出現在他的 App 通知裡，按「加入」就好，不用掃 QR Code。
- 不需要你核准，但計入 30 人上限。
- **App 介面不顯示人數上限、名額或還剩幾位**；這些只出現在管理後台。額滿時邀請者只看到：「目前沒辦法邀請新的人加入，請聯絡邀請你的人。」
- 你在後台的邀請清單看得到所有邀請，包括使用者發出的，必要時可以撤銷。

**受邀者的註冊流程**

1. 點開連結，打開 App 的註冊頁。email 已經帶入、不能修改。
2. 選擇登入方式，完成註冊：
   - **設定密碼**（M1）：不用收驗證信，因為持有邀請連結就代表是受邀者本人。
   - **用 Google 登入**（M1）：Google 帳號的 email 必須和受邀的 email 相同。
3. 註冊完成後，邀請狀態變成「已接受」，直接進入新手引導。

**忘記密碼**

App 不寄信，所以不能自助重設密碼：

- 登入頁的「忘記密碼」會說明：「請聯絡邀請你的人，取得重設密碼的連結。」
- 你在後台的使用者清單按「產生重設密碼連結」，連結 24 小時內有效、只能用一次，一樣自己傳給對方。
- 用 Google 登入的人不會遇到這個問題。
- 不做 Apple 登入（需要付費的 Apple 開發者帳號）；iPhone 的人用密碼或 Google 登入。

**沒有受邀的人**

- 打開 App 只會看到登入頁和「目前只開放受邀使用」：
  > 叮！這裡目前是私人廚房，只招待受邀的朋友。想來的話，先留個 email 吧。
- 可以留下 email 加入等候名單（P1）。你在後台幫他產生邀請連結，再用「用我的信箱寄」寄給他。

**管理**

產生邀請連結、管理使用者都在管理後台的「使用者與邀請」模組，見 [L. 管理後台](#l-管理後台)。

| 功能 | 優先級 | 說明 |
|------|-------|------|
| 產生邀請連結 | P0 | email、備註、方案、「也邀請他加入我的廚房」；複製、分享、用我的信箱寄、QR Code |
| 邀請清單 | P0 | 待接受／已接受／已過期／已撤銷。可以重新產生連結、撤銷、延長期限、修改 email（尚未接受時） |
| 使用者清單 | P0 | 註冊時間、最後使用時間。可以停用帳號、調整方案、產生重設密碼連結 |
| 使用人數上限 | P0 | 預設 30 人（已註冊＋還沒過期的待接受邀請合計），達到上限就不能再產生邀請 |
| 等候名單 | P1 | 一鍵產生邀請連結或略過 |
| 註冊模式 | P1 | 只限邀請／邀請＋等候名單／開放註冊。公開上線時切換，不用改程式 |
| 使用者邀請家人（廚房邀請） | M2 | 同一個邀請表單、勾選加入廚房；不需核准，計入人數上限（見上方） |
| 讓使用者邀請朋友（一般邀請） | P2（M4） | 同一個表單、不勾加入廚房；目前只有管理者能發。M4 開放時每人 2 個名額，計入人數上限，你可以在後台個別調整；App 不顯示剩幾個名額，用完時說明「目前沒辦法再邀請，請聯絡管理者」 |

**規則**

| 規則 | 說明 |
|------|------|
| 連結綁定 email | 只能用受邀的 email 註冊 |
| 一次性 | 註冊完成後連結就失效 |
| 有效期限 | 預設 14 天。重新產生會換新連結，舊的同時失效 |
| email 比對 | 不分大小寫，其他部分必須完全相同 |
| 撤銷邀請 | 還沒接受的立即失效。已經註冊的帳號要另外「停用」 |
| 停用帳號 | 無法登入，所有功能都停止；資料保留，可以恢復 |

**這個做法的取捨**

- **email 沒有經過驗證**：密碼註冊時不寄驗證信，持有連結的人就能用那個 email 註冊。所以連結請私下傳給本人；如果被轉傳，在對方註冊前撤銷即可。以「自己和朋友」的規模，這個風險可以接受。
- **email 打錯也能用**：密碼登入只把 email 當帳號名稱，打錯仍能登入，只是之後無法用 Google 登入。邀請在接受前可以修改 email。
- **公開上線前要補寄信服務**：開放註冊後，需要自助重設密碼、驗證 email、等候名單通知，到時再接寄信服務與寄件網域。

## L. 管理後台

> 給系統管理者（你）使用。和 App 是同一個網站，網址是 `/admin`，只有管理員帳號能進入。以電腦操作為主，手機也能看。

**原則：看得到營運，看不到別人的生活**

使用者的料理與帳號資料屬於使用者自己（產品原則 9「分享由你決定」）。管理後台只顯示**統計數字與帳號資料**（人數、用量、費用、狀態），**不提供瀏覽使用者私人食譜、食材、照片的功能**。例外只有兩種（公開上線前加入檢舉功能後會多一種）：

- 已經公開的分享頁內容，為了能下架不當內容。
- 使用者回報問題時，主動勾選「允許管理員查看這筆資料」的那一筆。
- 公開上線前：好友檢舉的那一筆社群內容（見下方「檢舉處理」）。檢舉者原本就看得到它。

身為資料庫擁有者，你技術上仍然能直接查資料庫。隱私說明會如實告知這一點，並承諾只在除錯、而且經過使用者同意時才這麼做。

**功能模組**

| 模組 | 功能 | 階段 |
|------|------|------|
| 使用者與邀請 | 產生邀請連結、邀請清單、使用者清單、人數上限、等候名單（見 [K 節](#k-帳號與邀請制註冊)）；調整方案與個人的合理使用上限；停用、恢復帳號，或只暫停某人的 AI；產生重設密碼連結 | M1 |
| 邀請來源 | 邀請清單顯示發出的人（你或使用者）、類型（一般／廚房邀請）、要加入的廚房、狀態、到期日，可以撤銷還沒被接受的；使用者清單顯示每個人是誰邀請、經由哪種邀請加入；名額拆成「已註冊／待接受（你發的）／待接受（使用者發的）」 | M2 |
| AI 用量與成本 | 本月費用與預算進度、依任務類型和模型拆分的 token 用量、每位使用者用量排行、快取命中率、失敗與拒答次數；**異常使用**清單（被速率限制或合理使用上限擋下、異常偵測標記的帳號） | M1 基本／M2 完整 |
| 系統設定 | 註冊模式、人數上限、刪除後可以復原的天數（預設 30 天）、AI 每月預算、用量保護的數值（速率限制、各方案的合理使用上限）；各任務使用的 AI 模型（唯讀） | M1 |
| 操作紀錄 | 管理員的每個操作（誰、什麼時間、做了什麼）都留下紀錄，不能修改或刪除 | M1 |
| 總覽 | 註冊人數、近 7 天／30 天活躍人數、待接受的邀請、本月 AI 費用與預算進度、儲存空間用量、近期錯誤數 | M2 |
| 分享連結 | 所有公開分享頁的清單（建立者、瀏覽數）；下架不當內容 | M2 |
| 回饋收件匣 | 使用者在 App 裡「回報問題／給建議」的內容；AI 建議被按「不想要」的原因統計 | M2 |
| 檢舉處理 | 好友檢舉的內容（食譜、留言、個人料理頁）排成待處理清單；只顯示被檢舉的那一筆和檢舉原因。可以「下架」或「不處理」，並寫一句處理說明；同一個人被檢舉、被下架的次數會列出來，需要時再到「使用者與邀請」停用帳號（見下方「檢舉處理」） | 公開上線前 |
| 廚房 | 廚房清單：名稱、成員人數、管理者人數、建立日期、有沒有正常的管理者；**不顯示食材、廚具或任何內容**。廚房沒有可用的管理者時（唯一的管理者帳號被停用，或成員回報求助），可以指定一位現有成員當管理者（見下方「廚房求助」） | M2 |
| 公告 | 對所有使用者顯示一則公告（維護時間、新功能），可設定顯示期間 | M2 |
| 產品數據 | 主指標「每月有料理交流的人數比例」的趨勢；社群、記錄、靈感、留存、食材、穩定度、成本的月趨勢；點子、記錄、新手引導的漏斗；功能的到達率與完成率；微問卷結果。**只顯示匯總**，少於 5 人的分組不顯示，不能查單一使用者（見 [14 產品成效與使用數據](14-product-metrics.md)） | M2 |
| 字典審查 | 使用者輸入、但字典裡沒有的食材與廚具名稱，依出現次數排序；抽查 AI 自動對應的食材是否正確 | M3 |
| 功能開關 | 讓部分使用者先試用新功能（例：用說的改食譜） | M3 |

**AI 每月預算**

- 每月預算預設 US$18，可在系統設定調整（親友使用階段每月營運總額 US$20，Supabase 與 Netlify 用免費方案）。
- 用到 80% 時通知你：後台頂端顯示醒目提示，你自己的 App 首頁也會出現提醒（M2 起再加推播通知）。App 不寄信。同時首頁點子改用較便宜的模型、靈感彩蛋改用模板，對話不受影響（見 [03 換模型的規則](03-ai-design.md#模型選擇)）。
- 用到 100% 時，App 內建的 AI 功能自動改用不用 AI 的推薦，不再呼叫 AI。大廚會說：「這個月點子想太多，燈泡要休息一下，先從你的食譜裡挑。」你在後台提高預算，就立刻恢復。
- 背景任務（發佈後整理等）暫停排隊，等下個月或預算提高後再處理。

**檢舉處理**（公開上線前）

> 初期只有親友使用，**不做檢舉功能**。遇到不舒服的內容，使用者用移除好友、不看動態、刪除自己內容下的留言自己處理；真的需要時，直接用「回報問題」或私下聯絡你。以下是對外公開前要做的設計。

1. 使用者在好友的食譜、留言或料理頁上按「檢舉」，選原因（不當內容、騷擾、侵權、其他）。檢舉者可以同時封鎖對方（封鎖也是公開上線前才做），不用等你處理。
2. 後台的「檢舉處理」出現一筆待處理，總覽頁也會顯示待處理數量。
3. 你只看得到被檢舉的那一筆內容與原因，看不到對方其他的食譜。
4. 處理方式：
   - **下架**：食譜只剩作者自己看得到，從所有人的動態、料理頁與收藏中消失；留言直接移除。作者收到通知：「你的一篇食譜因為被檢舉而下架：（你寫的說明）。有疑問請聯絡邀請你的人。」
   - **不處理**：內容維持原狀，檢舉者不會收到結果（避免變成互相監視）。
5. 每一次處理都寫進操作紀錄。

**廚房求助**（M2）

廚房規則要求至少一位管理者，正常情況下不會卡住（最後一位管理者離開或刪除帳號前，必須先指定接手者）。只有兩種情況需要你：

- 唯一的管理者帳號被你停用了。
- 成員回報問題：「我們家的管理者已經不用這個 App，沒辦法改廚房設定」。

這時你在「廚房」模組指定一位現有成員當管理者。你只看得到廚房名稱和成員名單（帳號資料），看不到食材和廚具。指定後，廚房的所有成員都會收到通知「系統管理員指定了小美為廚房管理者」，並寫進操作紀錄。你不能把自己加進別人的廚房。

**產品數據的隱私**

- 只記「做了什麼操作」，不記內容；事件只存在自己的資料庫，不用第三方分析工具。
- 使用者可以在「我的 → 設定 → 隱私」關閉「參與使用統計」；關閉後不記錄事件，也不會出現微問卷。
- 事件清單、指標定義、保留期限見 [14](14-product-metrics.md)。

**刻意不放在後台的**

- **字典與安全參考表的正式修改**：仍然在程式碼庫修改、經過審查後隨版本發佈，保留完整的修改與審核紀錄。後台只負責收集和審查建議。中心溫度、舒肥組合這類安全資料尤其如此。
- **資料庫的底層操作**：需要時直接用 Supabase 的管理介面，只作為緊急用途。

**安全**

- 管理員帳號必須啟用兩步驟驗證（驗證器 App）。
- 一般使用者的 App 不會下載後台的程式碼。

## M. 料理社群

> 透過料理認識彼此、建立共同的興趣。像一個只屬於朋友圈的料理版 Instagram：加好友、看彼此的料理頁、欣賞好友記錄的料理、互相分享與收藏食譜。每個人記錄的本來就是值得記住的料理，所以社群自然以「作品」為主，沒有「今天誰煮了什麼」的每日感。
>
> **社群是這個 App 的核心**：首頁就是朋友的動態與互動，加上大廚的點子。好友、動態、反應、留言、通知在 **M2** 上線；口味相似度、共煮挑戰等延伸功能在 M3、M4。

### 原則：每一筆都由你決定誰看得到

食譜**預設給好友看**，每一篇都由你決定，可以隨時改：

| 可見範圍 | 誰看得到 | 適用 |
|---------|---------|------|
| 🔒 只有自己 | 只有你 | 草稿、食材、口味地圖、設定永遠是這一級；食譜可以選 |
| 🏠 家人 | 同廚房的成員 | 食譜（進入家庭食譜本，M2 起，見「核心概念：廚房與家人」） |
| 👥 好友 | 同廚房的家人＋已互加的好友 | **食譜的預設值**；個人料理頁的各區塊 |
| 🔗 公開連結 | 任何拿到連結的人 | 單一食譜（既有的分享連結，見 G 節） |

- 範圍由小到大：只有自己 → 家人 → 好友（含家人）。
- 記錄食譜時，發佈按鈕旁顯示「👥 好友看得到」，點一下就能改成只有自己或家人。預設值可以在設定裡改。
- 第一次發佈時，大廚會說明一次：「這篇會出現在好友的首頁。想自己留著的話，點這裡改成只有自己。」
- 從網址匯入的食譜，預設「只有自己」：可能是別人的作品，由使用者決定是否分享。
- 縮小範圍（例如改回「只有自己」）會立刻從其他人那邊消失。
- **永遠不會給好友看的**：食材（同廚房的家人本來就共用）、過敏原與飲食限制（除非你在 P2 的「讓好友知道我的過敏原」中主動開啟）、AI 用量、帳號設定。

### 好友

| 功能 | 優先級 | 說明 |
|------|-------|------|
| 加好友 | P0 | 用「好友連結」或 QR Code 加好友（例：當面掃、傳 LINE）。對方確認後成為好友（雙向） |
| 邀請者自動成為好友 | P0 | 透過邀請連結（管理者的或家人的）註冊的人，預設和邀請者成為好友，可以取消勾選 |
| 好友清單 | P0 | 頭像、暱稱、近況、最新記錄的一道菜。不顯示下廚頻率，避免互相比較 |
| 不看動態 | P0 | 對某位好友「不看動態」，仍是好友，只是不出現在你的動態中，對方不會知道 |
| 移除好友 | P0 | 雙方都不再看得到彼此「好友」範圍的內容，對方不會收到通知 |
| 封鎖 | 公開上線前 | 移除好友，並讓對方無法再送出好友邀請。初期只有親友使用，先不做 |
| 你可能認識 | P2 | 列出「好友的好友」，需要雙方都開啟這個選項 |

### 個人料理頁

每個人都有一頁給好友看的料理頁，像料理版的個人主頁：

| 區塊 | 內容 | 預設 |
|------|------|------|
| 頭像與簡介 | 暱稱、頭像、一句話自我介紹（「週末限定的烘焙魂」） | 顯示 |

- 料理偏好是從你的資料計算出來的，只有你按下「發佈」才會更新到料理頁，不會自動外流。

### 分享與收藏好友的食譜

| 功能 | 優先級 | 說明 |
|------|-------|------|
| 分享給好友 | P0 | 在食譜頁選好友、附一句話送出。對方在「好友送來的食譜」收到，並收到通知。送給好友時，對方可以看到這份食譜，即使可見範圍是「只有自己」。作者可以隨時收回；刪除食譜或移除好友時自動失效，對方看到「這道菜已收起來了」 |
| 收藏 | P0 | 把好友的食譜加進你的「食譜」頁。收藏的是原作，好友更新內容你也看得到；好友改回「只有自己」、刪除，或你們不再是好友時，只留下菜名與「這道菜已收起來了」，不保留做法（分享由作者決定）。收藏頁提示「想永久留著，就記錄成你的版本」 |

### 通知中心

在「我的」裡面，有新通知時「我的」分頁出現紅點，收齊所有社群通知（P0）：好友邀請、加入廚房的邀請、成為好友、好友送來的食譜、料理反應與留言、食譜被收藏，以及 M4 的「我做了你的菜」。每一類都可以在設定中關閉。推播通知在 M2 推播功能完成後，依各類開關提供。

| 點子 | 說明 |

| 口味相似度 | 兩人都發佈了料理偏好時，顯示「你和小美的口味相似度 78%」，以及你們都愛的醬料 |

### 安全

- 初期只有親友使用，**不做檢舉**。每個人都可以自己處理：不看動態、移除好友、刪除自己內容下的留言，都不需要經過管理員。
- 真的遇到問題時，用「回報問題」或私下聯絡你。
- **公開上線前**才加入檢舉與管理員下架，設計見 [L 節](#l-管理後台)的「檢舉處理」。

## 之後可以擴充與檢討

上線後依實際使用再看的事。類型：**擴充**＝之後可以加的功能；**優化**＝讓現有的更好；**檢討**＝回頭確認當初的決定還對不對。全部項目依時間整理在 [08 第四部分](08-open-items.md#四之後可以擴充優化或檢討)。

| 項目 | 類型 | 什麼時候看 | 怎麼判斷 |
|------|------|-----------|---------|
| 和家人一起跟大廚聊 | 擴充 | M4（和「今晚想吃什麼投票」一起） | 同廚房的家人在同一段對話裡提需求，大廚合併大家的條件 |
| 收藏分類 | 擴充 | 有人收藏超過 50 篇時 | 收藏太多找不到時，加自訂分類（例：「招待朋友」「便當」） |
| 「想做」標記 | 檢討 | M2 後 | 收藏不分想做與喜歡；如果訪談中常有人想區分「想做」和「只是喜歡」，再加一個選填的標記 |
| 從瀏覽器直接收藏網頁 | 擴充 | M3 後 | Android 可以讓 App 出現在分享選單裡，網頁一鍵匯入；iOS 的 PWA 不支援，要另外想做法 |
| 拍手寫食譜 | 擴充 | 有人想保存家傳食譜時 | 拍手寫食譜或食譜書頁面，AI 轉成結構化食譜並保留原圖；這是唯一會把照片送給 AI 的功能，要先比較讀手寫中文的準確度與成本 |
| 解鎖類功能 | 擴充 | M3 後再評估 | 料理護照、手法護照、料理稱號、里程碑徽章、社群成就。先從訪談確認使用者想要多樣性的回饋，而且不會變成「收集」的壓力，再決定要不要做 |
| 列出要買的：合併多道菜 | 擴充 | M3 後 | 一次選幾道收藏，合併成一份食材清單再送到提醒 App |
| 難易度依個人 | 擴充 | 難易度上線半年後 | 同一道菜，對常下廚的人顯示較低的分數（「對你來說」），作者看到的仍是原始分數 |
| 大約的時間 | 檢討 | 難易度上線三個月後 | 如果很多人在對話中問「要多久」，考慮讓作者選填「大約半小時」這類文字，不給精準分鐘數 |
| App 內錄音 | 擴充 | 「用說的」上線三個月後 | 鍵盤聽寫不好用（講太長、手上有油不方便按）時，評估 App 內錄音再轉文字；要多一筆語音服務的費用 |
| 標示「大廚整理」 | 檢討 | 發生過敏或做錯的回報時 | 目前不標示；如果朋友照做出問題，考慮加上「作者已確認」或「大廚整理」的標示 |
| 公開後的名額顯示 | 檢討 | 公開上線前 | 開放註冊後，使用者自己的邀請名額要不要讓他看到 |
