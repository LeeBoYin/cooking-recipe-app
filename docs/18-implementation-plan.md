# 18 實作計劃

**用途**：把路線圖（[06](06-roadmap.md)）與後端建置順序（[16 第十一節](16-backend-implementation.md#十一建置順序)）切成一段一段的開發工作。每一段是一個分支、一個 PR，也是一個 session 的量。開工時照這份領下一段。

---

## 一、怎麼用這份計劃

**每一段的進行方式**
1. 開新 session，先讀這份計劃裡該段的「讀」欄，再讀對應的規格。
2. 照開發慣例走一條直線：資料表與 RLS → 權限測試（pgTAP）→ 資料庫函式 → 前端資料存取層 → 畫面 → 端對端測試。沒有資料庫的段落略過前幾步。
3. 自己驗證：`pnpm typecheck`、`pnpm test`、`pnpm db:test`、`pnpm check:deno`、`pnpm build`，畫面要實際跑過。沒驗證到的在 PR 說明寫清楚。
4. 實作和規格不一致時先停下來問；確定後程式和文件一起改。
5. PR 合併後：把這份計劃該段的 `[ ]` 改成 `[x]`，更新 `CLAUDE.md` 的目前狀態，再開新 session。

**欄位說明**
- **模型**：「Sonnet」＝規格已定，照著做；「Opus 先討論」＝先開 Opus 把方案談定、寫進規格，再切 Sonnet 實作。
- **讀**：這一段要先讀的規格章節。
- **估計**是一個 PR 的量；做的時候範圍超過就再拆，不硬塞。

**不在這份計劃裡的**：M3、M4、公開上線前的工作。M2 完成後再依當時的狀況切。
