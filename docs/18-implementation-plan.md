# 18 實作計劃

**用途**：把路線圖（[06](06-roadmap.md)）與後端建置順序（[16 第十一節](16-backend-implementation.md#十一建置順序)）切成一段一段的開發工作。每一段是一個分支、一個 PR，也是一個 session 的量。開工時照這份領下一段。

---

## 一、怎麼用這份計劃

**每一段的進行方式**
1. 開新 session，先讀這份計劃裡該段的「讀」欄，再讀對應的規格。
2. 照開發慣例走一條直線：資料表與 RLS → 權限測試（pgTAP）→ 資料庫函式 → 前端資料存取層 → 畫面 → 端對端測試。沒有資料庫的段落略過前幾步。
3. 自己驗證：`pnpm typecheck`、`pnpm test`、`pnpm db:test`、`pnpm check:deno`、`pnpm build`，畫面要實際跑過。沒驗證到的在 PR 說明寫清楚。
4. 實作和規格不一致時先停下來問；確定後程式和文件一起改。
5. PR 合併後：把這份計劃該段的 `[ ]` 改成 `[x]`，更新 `CLAUDE.md` 的目前狀態，再開新 session。

**欄位說明**
- **模型**：「Sonnet」＝規格已定，照著做；「Opus 先討論」＝先開 Opus 把方案談定、寫進規格，再切 Sonnet 實作。
- **讀**：這一段要先讀的規格章節。
- **估計**是一個 PR 的量；做的時候範圍超過就再拆，不硬塞。

**不在這份計劃裡的**：M3、M4、公開上線前的工作。M2 完成後再依當時的狀況切。

  - 跟手：抽屜位移等於手指位移，背景遮罩跟著變淡。
  - 關閉門檻：放開時位移超過抽屜高度的 25%，或往下的速度超過 0.5px/ms，就關掉。
  - 回彈：沒過門檻就彈回原位；拖到一半又推回去也算沒過。
  - `prefers-reduced-motion` 時不放動畫，直接關或回原位。
  - 做成共用的抽屜元件，`ChoiceSheet`、`ShoppingSheet`、`InstallSheet` 一起換。
- 底部按鈕改成收藏切換：沒收藏顯示「收藏」，收藏了顯示「已收藏」，再按一次取消。卡片右上角的收藏保留，兩邊狀態一致。
- 拿掉「就聊這道」：抽屜的按鈕、`onChat`、代送「想做〇〇」的程式，以及對話提示詞裡「使用者說『想做〇〇』」那條規則。

**09c 首頁點子輪播**

- 卡片寬度是螢幕寬度減 48px，左右各露出前後一張約 16px 的邊。卡片變寬之後，菜名與理由完整顯示，不截斷。

- 主要食材：卡片的「食材廚房有」改成主要食材的標籤，取點子用到的廚房食材與使用者提到的食材，最多 3 個，超過的顯示「+N」。沒有任何食材時顯示難度標籤。對話裡的卡片用同一套標籤。

**09d 收藏的點子**

**09e 廚房清單與齒輪**

**09f 和大廚聊聊 ③：多輪收斂**

### M1a-09g～09i：畫面細修與 iOS 外殼

三段只改前端（09h 另外改 `chat` 任務），檔案不重疊，可以同時做。09i 的轉場要做成全站共用（路由與外殼），不改各畫面的檔案；做不到時先停下來問，等 09g 合併再改。每段做完把規格寫進 17（以及 03、09 對應的段落）。09h、09i 要在 iPhone 上看過才合併（狀態列的模糊另外研究，不在這三段）：先用 iOS 模擬器的「加入主畫面」自己驗，再請使用者用手機開預覽網址確認。

**09g 畫面細修**

- 刪除食譜：先重現「刪除後卡在找不到食譜」，確認原因（多半是瀏覽紀錄裡還留著那篇食譜頁，回去時顯示找不到）。修法：刪除成功回到「食譜」清單；食譜頁讀到已刪除或找不到的食譜時，直接換成「食譜」清單（`replace`），不停在找不到的畫面。
- 廚房小卡右上角的狀態小圖示（刪除、快到期、想先用掉）：圓形、中心放在卡片的右上角，一半突出卡片外；加一圈背景色的外框，和卡片邊界分開。卡片與網格要留出突出的空間，不能被裁掉。
- 廚房小卡的品項圖示放大約 1.5 倍，以手機 375px 寬看得清楚、名稱不被擠掉為準。
- 廚房動作列（食材、廚具共用）同一行：左邊「快速盤點」，右邊「編輯」、「＋ 新增」並列。三個都是圖示＋文字、沒有外框；「快速盤點」「編輯」灰字無底色，「新增」用淡淡的主色底、深色字，是這一行唯一的重點。編輯模式時「編輯」變成「完成」。原本的編輯切換拿掉。
- 食譜頁的搜尋列和「食譜／收藏」切換放在同一行：搜尋列在左、佔剩下的寬度，切換在右、照內容寬度。兩個分頁共用同一個搜尋字，切換分頁時保留。「收藏」也能搜尋：在手機端比對點子名稱與主要食材，不加後端函式（收藏的數量少）。
- 收藏卡片：拿掉「看做法」與「取消收藏」（整張卡片點了就打開完整頁，完整頁裡有取消收藏）。「還沒做過／做過了」和主要食材標籤排在同一行，放不下的食材標籤不顯示，不換行。
- 首頁點子輪播：「換一組」改成輪播的最後一張卡片（大廚的小圖＋「換一組」），不再佔一行；圓點也算這一張。沒有下一組時不放這張。按下「換一組」後，整組先換成和點子卡同尺寸的骨架卡（shimmer），回到第一張，拿到新點子再換回來；第一次打開、沒有上次的點子時也用同一種骨架。開啟「減少動態效果」時骨架不閃。

**09h 和大廚聊聊 ④**

- 鍵盤：iPhone 的鍵盤出現時版面高度（`dvh`）不會變小，輸入框被擋住。改成依 `visualViewport` 的高度與位置設定對話頁的高度，鍵盤出現、收起時跟著調整，訊息列表保持捲到最底。只改對話頁。
- 接著聊的提示：`chat` 的輸出加 `hint`（一句使用者可能接著說的話，例：「那配菜呢？」，不超過 20 個字，可以是 `null`）。程式檢查和 `ask` 一樣（字數、過敏原與排除的字）；沒過就只丟掉 `hint`，其他欄位照用。輸入框的提示文字在有 `hint` 時顯示「例如：那配菜呢？」，沒有時用原本的。這一輪有選項按鈕時不顯示 `hint`。提示只是提示，空白送出不會代送。評估集加上 `hint` 的檢查。

**09i iOS 外殼與轉場**

- 直向顯示：manifest 加 `orientation: 'portrait'`（Android 安裝後會鎖住）。iOS 不支援，不另外處理，不用 CSS 旋轉畫面。
- 下層頁的轉場：主要畫面是底部分頁列裡的畫面；下層頁是有「返回」的內頁與對話頁。用 View Transitions API：
  - 進入下層頁（含下層頁再進下層頁）：新頁從右邊滑入，上一頁往左移約 30%、稍微變暗。
  - 離開（按返回、瀏覽器上一頁）：目前這頁往右滑出，上一頁回到原位。
  - 主要畫面之間（底部分頁、頁內的分頁切換）沒有動畫；直接打開網址的第一次載入也沒有。
  - 約 300ms、ease-out，只用 transform 與 opacity（變暗用舊畫面的 opacity）。快照動畫本來就會等播完才換掉舊畫面。
  - 回到上一頁時保留原本的捲動位置。
  - 開啟「減少動態效果」時改成很短的淡入淡出。
  - 不支援 View Transitions 的瀏覽器沒有動畫，功能不變。
  - 手勢返回：Safari 瀏覽器裡往右滑返回時，系統已經有自己的動畫，App 不再播，避免疊兩層。做法是 App 的「返回」按鈕在返回前先做記號：有記號的返回才播離開動畫；沒有記號的返回（手勢、瀏覽器上一頁）在 Safari 瀏覽器裡不播。加到主畫面（standalone）時沒有手勢返回，返回一律播。
  - 先做小實驗確認：瀏覽器上一頁（`popstate`）能觸發動畫；需不需要把路由改成 `createBrowserRouter`；在 iOS 模擬器的 Safari 裡用手勢返回，確認不會疊兩層動畫。

**可以平行的內容工作**：食材字典擴充到 800–1500 筆、基礎菜色補到 300–500 道（見 08），另開 session 做，不擋 M1a。

**M1a 驗收**（見 06）：點子被採用的比例、對話後有收藏或記錄的比例、平均每人每月的 AI 成本、訪談偶爾使用的朋友仍覺得好用。
