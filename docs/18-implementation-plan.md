# 18 實作計劃

**用途**：把路線圖（[06](06-roadmap.md)）與後端建置順序（[16 第十一節](16-backend-implementation.md#十一建置順序)）切成一段一段的開發工作。每一段是一個分支、一個 PR，也是一個 session 的量。開工時照這份領下一段。

---

## 一、怎麼用這份計劃

**每一段的進行方式**
1. 開新 session，先讀這份計劃裡該段的「讀」欄，再讀對應的規格。
2. 照開發慣例走一條直線：資料表與 RLS → 權限測試（pgTAP）→ 資料庫函式 → 前端資料存取層 → 畫面 → 端對端測試。沒有資料庫的段落略過前幾步。
3. 自己驗證：`pnpm typecheck`、`pnpm test`、`pnpm db:test`、`pnpm check:deno`、`pnpm build`，畫面要實際跑過。沒驗證到的在 PR 說明寫清楚。
4. 實作和規格不一致時先停下來問；確定後程式和文件一起改。
5. PR 合併後：把這份計劃該段的 `[ ]` 改成 `[x]`，更新 `CLAUDE.md` 的目前狀態，再開新 session。

**欄位說明**
- **模型**：「Sonnet」＝規格已定，照著做；「Opus 先討論」＝先開 Opus 把方案談定、寫進規格，再切 Sonnet 實作。
- **讀**：這一段要先讀的規格章節。
- **估計**是一個 PR 的量；做的時候範圍超過就再拆，不硬塞。

**不在這份計劃裡的**：M3、M4、公開上線前的工作。M2 完成後再依當時的狀況切。

### M1a-09b～09f：大廚與點子的體驗改善

09b、09c、09d、09e 只改前端，檔案不重疊，可以同時做。09f 要等 09b 合併（兩段都動到對話頁）。每段做完時把規格同步寫進 02、03、09、17 對應的段落。

**09b 點子抽屜**
- 可拖曳關閉（drag-to-dismiss）：
  - 捲動交接：內容捲到最上面之後再往下拉，就變成拖抽屜，不再捲內容；把手也能拖。
  - 跟手：抽屜位移等於手指位移，背景遮罩跟著變淡。
  - 關閉門檻：放開時位移超過抽屜高度的 25%，或往下的速度超過 0.5px/ms，就關掉。
  - 回彈：沒過門檻就彈回原位；拖到一半又推回去也算沒過。
  - `prefers-reduced-motion` 時不放動畫，直接關或回原位。
  - 做成共用的抽屜元件，`ChoiceSheet`、`ShoppingSheet`、`InstallSheet` 一起換。
- 底部按鈕改成收藏切換：沒收藏顯示「收藏」，收藏了顯示「已收藏」，再按一次取消。卡片右上角的收藏保留，兩邊狀態一致。
- 拿掉「就聊這道」：抽屜的按鈕、`onChat`、代送「想做〇〇」的程式，以及對話提示詞裡「使用者說『想做〇〇』」那條規則。

**09c 首頁點子輪播**
- 一次只看到一張：`scroll-snap-type: x mandatory`，每張 `scroll-snap-stop: always`，一次滑一張。
- 卡片寬度是螢幕寬度減 48px，左右各露出前後一張約 16px 的邊。卡片變寬之後，菜名與理由完整顯示，不截斷。
- 卡片下方是圓點指示，目前那張的圓點填滿；用 IntersectionObserver 判斷目前是第幾張。圓點只是指示，不能點。
- 主要食材：卡片的「食材廚房有」改成主要食材的標籤，取點子用到的廚房食材與使用者提到的食材，最多 3 個，超過的顯示「+N」。沒有任何食材時顯示難度標籤。對話裡的卡片用同一套標籤。

**09d 收藏的點子**
- 「食譜 → 收藏」裡大廚點子的卡片，加上主要食材標籤（同 09c）。
- 點卡片打開完整一頁 `/recipes/saved/:bookmarkId`，排版像食譜頁：菜名、理由、食材（標「你說的」「廚房有」）、步驟。還沒展開過做法的，打開時才請大廚寫（`expand_steps`），等待與失敗的畫面沿用抽屜的。
- 底部的動作：收藏切換（取消之後留在頁面，可以再按回來；離開頁面才從清單消失）、「做了，記錄一篇」（帶入食材與步驟，和現在一樣）、記錄過的話再加「打開我記錄的那篇」。
- 收藏分頁不再打開抽屜。

**09e 廚房清單與齒輪**
- 食材與廚具清單改成小卡片網格，4 欄，和盤點頁一樣：圖示（廚具有照片就用照片）加名稱，不放標籤。區域標題（冷藏、冷凍…）保留。點卡片進編輯頁。
- 移除：清單上方有「編輯」按鈕，按下進入編輯模式（按鈕變「完成」）。編輯模式裡每張卡片右上角換成刪除小圖示（蓋過狀態圖示），點了就移除：食材和現在一樣直接移除（可以從「最近刪除」救回），廚具和現在一樣先確認。編輯模式裡點卡片本身不進編輯頁；離開頁面就結束編輯模式。編輯頁的移除保留。
- 卡片右上角的浮動小圖示，最多一個，依序：已過期（紅色時鐘）→ 快到期（時鐘，用現有的快到期判斷）→ 想先用掉（燈泡）。圖示要有文字給讀螢幕的人（例：「快到期」）。
- 廚具的細節（尺寸、材質）不放在卡片，只在編輯頁。
- 齒輪圖示換成 Lucide 的 `settings`（ISC 授權，在檔案註明來源），線寬與其他圖示一致。

**09f 和大廚聊聊 ③：多輪收斂**
- 流程分三步：盤點食材（還有別的嗎、份量夠嗎）→ 問想吃的風味與風格 → 收斂。至少 3 輪大廚的回應（含這一則）才給點子；使用者點「直接給我點子」或明說要點子時，馬上給。
- 每一輪大廚可以附 2 到 4 個選項，單選或多選。`ask` 改成 `{ question, options, multi }`；選項顯示成按鈕，點了就送出（多選時有「好了」），使用者也能自己打字。還沒給點子的每一輪都另外有「直接給我點子」。
- 收斂後給 1 到 2 個點子。給完不出現「開新的一段」，輸入框不鎖，使用者想延續就繼續聊。
- 盡量用到所有提到的食材：寫進提示詞，程式也檢查。使用者說了 3 樣以上、點子只用到 1 樣時，整批重寫一次；重寫還是不行就照樣給。真的搭不起來的，大廚在 reply 說哪幾樣適合留到下次（不寫成催促）。
- 對話裡的點子卡片列出「你提到的食材」：每一樣都列，這道有用到的標綠色，沒用到的標灰色。
- 對話頁的 20 輪上限、摘要、過敏原與安全規則的檢查不變。評估集改寫成多輪（盤點、問風味、收斂、直接給我點子、食材搭不起來），跑法照 `spikes/README.md` 07。

**可以平行的內容工作**：食材字典擴充到 800–1500 筆、基礎菜色補到 300–500 道（見 08），另開 session 做，不擋 M1a。

**M1a 驗收**（見 06）：點子被採用的比例、對話後有收藏或記錄的比例、平均每人每月的 AI 成本、訪談偶爾使用的朋友仍覺得好用。
