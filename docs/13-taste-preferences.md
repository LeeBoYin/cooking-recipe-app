# 13 飲食偏好模型：口味地圖

**用途**：定義「大廚怎麼理解一個人的口味」。新手引導的口味探索（[12](12-onboarding.md)）、點子的評分（[03](03-ai-design.md)）、偏好設定頁都以它為準。

---

## 一、設計目標

| 目標 | 做法 |
|------|------|
| **不用圖片，也能精準** | 用文字描述的菜餚、風格、食材、調味來問；一道菜的描述同時代表好幾個維度，回答一次就更新很多資訊 |
| **問得少、懂得多** | 自適應提問：先問大方向，只往使用者有興趣的方向深入；資訊夠了就停 |
| **有趣，不像問卷** | 描述生動的菜卡、二選一、爭議食材快問快答、口味光譜，交錯出現 |
| **硬限制絕不出錯** | 過敏、宗教與文化、飲食原則是硬性排除，和「喜好」分開處理 |
| **越用越懂你** | 記錄食譜、收藏、和大廚的對話、按「不想要」都會微調偏好；但不會悄悄推翻使用者親口說的 |
| **看得懂、改得動** | 所有偏好都能在「我的口味地圖」看到並修改；口味名片用人話描述 |
| **尊重隱私** | 宗教與文化只用來排除食材，送給 AI 的是「不含豬肉、酒精」這類結果，不是宗教標籤 |

---

## 二、偏好的維度

偏好分成三層：**硬限制**（絕對不能違反）、**喜好**（加減分）、**情境**（調整難度與型態）。

### 第一層：硬限制

| 類別 | 內容 | 怎麼套用 |
|------|------|---------|
| 過敏 | 依地區排序的主要過敏原：花生、堅果、蝦蟹、貝類、魚、蛋、牛奶、小麥（麩質）、大豆、芝麻…（字典 `Allergen`） | 含有的食材家族一律排除；AI 回傳後程式再檢查 |
| 宗教與文化 | 清真（不含豬、酒精；肉類來源無法確認時提醒）、佛教素／五辛素（不含肉類、蛋，以及蔥、蒜、韭、洋蔥、薤）、一般素食、印度教（不含牛）、猶太潔食（不含豬、帶殼海鮮；肉與奶不同餐，屬於「部分支援」）、不吃牛、不吃豬 | 每一條是一組「排除規則」（字典 `DietaryRestriction`）。規則太複雜、App 無法完整判斷的，標成「部分支援」並在點子上提醒 |
| 飲食原則 | 全素、蛋奶素、蛋素、奶素、海鮮素、鍋邊素（可以吃肉邊菜） | 同上 |
| 週期性規則 | **初一、十五吃素**（依農曆）、齋戒月、自訂「每週一無肉日」 | 只在那些日子套用排除規則；其他日子照常 |
| 料理用酒 | 不用酒（米酒、紹興、味醂含酒精） | 台式料理常用米酒，獨立一項，清真與不喝酒的人會用到 |

### 第二層：喜好（加減分）

每一項記一個**喜好程度**（−1 很不喜歡 ～ +1 很喜歡）和一個**把握程度**（0 完全不知道 ～ 1 很確定）。

| 維度群組 | 例子 | 結構 |
|---------|------|------|
| **地區與菜系** | 台灣（台式家常、小吃、客家、原住民料理）、日本（和食、洋食、居酒屋）、韓國、中國各地（川、粵、江浙、北方、雲貴）、東南亞（泰、越、馬來、印尼、菲律賓）、南亞（北印度、南印度）、中東、地中海（義、希臘、西班牙）、法國、美式（南方、BBQ、Tex-Mex）、墨西哥、拉丁美洲 | **樹狀**：先問大區，喜歡才往下問 |
| **基本味道** | 酸、甜、苦、辣、鹹、鮮，另加「麻」（花椒）、「香」（爆香、焦香）、「燻」 | 每一項一條光譜 |
| **辣的種類** | 麻辣（川）、酸辣（泰）、甜辣（韓）、香辣（台式辣椒醬）、咖哩辣、墨西哥辣椒 | 喜歡辣的人才問 |
| **調味系統** | 醬油系、味噌與柴魚系、魚露香茅系、咖哩香料系、番茄起司系、奶油香草系、豆瓣麻辣系、韓式醬系、BBQ 煙燻系、沙茶系 | 由菜卡回答推算，必要時直接問 |
| **口感** | 酥脆、軟嫩、Q 彈、滑順、有嚼勁、湯湯水水 | 二選一題推算 |
| **料理型態** | 湯、燉滷、快炒、燒烤、炸、蒸、涼拌、生食、一鍋料理、麵食、飯類、甜點烘焙 | 由菜卡與情境題推算 |
| **主要蛋白質** | 豬、雞、牛、羊、魚、蝦蟹貝、豆腐豆製品、蛋 | 快問快答 |
| **爭議食材** | 香菜、苦瓜、臭豆腐、內臟、生魚片、羊肉的羶味、藍紋起司、榴槤、茄子、秋葵、芹菜、薑 | 快問快答：愛／還好／不行。「不行」記成「不吃的食物」（軟性避開） |
| **濃淡** | 清爽 ↔ 濃郁、少油 ↔ 重油香 | 光譜 |

### 第三層：情境

| 項目 | 選項 | 用途 |
|------|------|------|
| 下廚頻率 | 偶爾，興致來才煮／一週幾次／幾乎每天 | 只用來調整點子的難度；不顯示給任何人 |
| 時間 | 平常願意花的時間：越快越好／普通／花時間也沒關係 | 點子難易度「時間」面向的上限（不換算成分鐘） |
| 為誰下廚 | 自己／另一半／家人小孩／招待朋友 | 預設份量、招待型點子 |
| 挑戰意願 | 0（好吃就好）～ 1（越新越好） | 「新挑戰」槽位的冒險程度 |
| 想學的方向 | 新菜系、甜點麵包、用好家裡的廚具、把家常菜做得更好吃 | 「新挑戰」的方向 |
| 節日料理 | 想在節日做應景菜（依廚房地區：冬至、中秋、尾牙；感恩節、聖誕節…） | 季節靈感 |

## 三、題型（全部不需要圖片）

| 題型 | 樣子 | 一題更新哪些維度 |
|------|------|----------------|
| **描述菜卡** | 「**泰式冬蔭功**：酸辣湯底，香茅、南薑、檸檬葉的香氣，加蝦和魚露」→ 😋 喜歡／🤩 想試試／🙂 普通／🙅 不愛 | 一次更新菜系、味道、辣的種類、調味系統、蛋白質、料理型態（約 6–8 個維度） |
| **二選一** | 「下雨天，你想吃… **一鍋濃郁的紅燒牛肉** 還是 **一碗清爽的味噌湯**？」 | 濃淡、料理型態、調味系統的相對偏好 |
| **口味光譜** | 「辣：🫑 一點都不要 ─── 🌶️ 麻辣鍋等級」兩端用熟悉的菜當例子 | 一個味道維度，把握程度直接拉高 |
| **快問快答** | 「香菜？」愛／還好／不行（一題一秒，連續 8–10 題） | 單一食材 |
| **原則選擇** | 過敏、宗教與文化、飲食原則的勾選 | 硬限制 |
| **情境題** | 「週末有空時，你比較想… 慢慢燉一鍋／挑戰沒做過的菜／簡單快速／烤點甜點」 | 情境與挑戰意願 |

描述菜卡的寫法：**菜名＋一句感官描述＋關鍵食材與調味**，30 字以內，讓沒吃過的人也能想像。「想試試」代表好奇，會提高挑戰意願，並把該方向列入「想學」。

## 四、自適應提問：怎麼問得少、懂得多

### 題庫

約 80–100 題，每題都標好它對應的維度與權重。例：

```jsonc
{
  "id": "card_tom_yum",
  "type": "dish_card",
  "title": { "zh-TW": "泰式冬蔭功" },              // 字典文字一律分語系
  "description": { "zh-TW": "酸辣湯底，香茅、南薑、檸檬葉的香氣，加蝦和魚露" },
  "regions": ["TW", "US"],                          // 哪些地區的使用者會看到
  "mapping": {                                      // 回答「喜歡」時各維度加多少；「不愛」時反向
    "cuisine.southeast_asia.thai": 0.8,
    "taste.sour": 0.5, "taste.spicy": 0.5, "spice_type.sour_spicy": 0.7,
    "seasoning.fish_sauce_lemongrass": 0.8,
    "protein.shellfish": 0.4, "form.soup": 0.4
  },
  "hardConstraintCheck": ["allergen.shellfish"],    // 有蝦蟹過敏的人不會看到這張
  "followUps": ["card_green_curry", "card_pho"]     // 喜歡時，接著可能問的題目
}
```

### 挑下一題的規則

每一題之前，程式依下面的分數挑出最值得問的題目：

```
題目價值 = Σ（該題涉及的維度：權重 × 目前的「不確定程度」 × 該維度對點子的影響力）
         − 和已回答題目的重複程度
```

- **先廣後深**：一開始的不確定程度都很高，所以會先挑覆蓋面廣的題目（不同大區的代表菜）。
- **只往有興趣的方向深入**：喜歡東南亞的菜卡，泰、越、馬來的後續題目價值就會提高；不喜歡的大區，下層題目不再出現。
- **硬限制先問**：新手引導在口味探索之前，用獨立的一步（[12 ④ 飲食限制](12-onboarding.md#④-飲食限制)）問過敏、飲食原則、宗教與文化，以及「還有其他不吃的嗎？」（從食材字典搜尋）。之後含有那些食材的題目都不會出現（不浪費使用者的時間，也不讓人看到不能吃的東西）。
- **矛盾時追問一題**：例如說「不吃辣」卻喜歡麻婆豆腐，就問「小辣可以嗎？」
- **題型交錯**：連續兩題不會是同一種題型，保持節奏。
- **知道得夠多就停**：主要維度的把握程度都超過門檻（例如 0.6），或已經問了 25 題，就結束並產生口味名片。使用者也可以隨時按「先這樣」。

### 兩種長度

| 模式 | 題數 | 時間 |
|------|------|------|
| 快速（預設） | 約 12–15 題 | 約 2 分鐘 |
| 深入（做完快速後可選「再多聊幾題」） | 再加 10–15 題 | 再 2 分鐘 |

新手引導用快速模式；想讓大廚更懂自己的人可以繼續。

## 五、口味名片與「我的口味地圖」

### 口味名片

由程式挑出最突出的幾個維度，套用預寫的命名組合：

> 💡 **香辣台式派**，偶爾想挑戰泰式
> 愛：醬油系、豆瓣麻辣、快炒與燉滷 ｜ 口感：軟嫩、湯湯水水
> 想學：做麵包
> 不吃：香菜 ｜ 過敏：蝦蟹 ｜ 初一十五吃素

- 名稱由「主菜系 × 主要味道」組合，例如「清爽日式派」「濃郁南洋魂」「什麼都好奇的探險家」（挑戰意願很高、喜好分散時）。
- 宗教與文化的項目只顯示使用者自己選的文字，不推論、不貼標籤。

### 我的口味地圖（偏好設定頁）

- 依三層列出所有維度，每項顯示目前的喜好程度。
- 每項都可以直接修改；修改後標成「你設定的」，之後自動學習不會覆蓋它（只會在明顯不一致時輕輕問一次）。
- 可以「重新探索」，或「再多聊幾題」。

## 六、越用越懂你

除了口味探索的回答（明確偏好），App 也從行為學習（隱含偏好），但權重較小：

| 行為 | 影響 |
|------|------|
| 記錄一道菜 | 該菜的維度 ＋（標成「家人最愛」「值得再做」、評分 😋 的加重；😅 翻車不扣分） |
| 收藏朋友的食譜或大廚的點子 | 該菜的維度 ＋（較小）；收藏的是「新挑戰」時，挑戰意願 ＋ |
| 在對話中說的偏好（「我不太吃羊肉」「最近想吃清淡的」） | 長期的偏好：該維度 ±（中等）；只針對今天的（「今天想吃熱的」）不寫入口味 |
| 按「不想要」：不愛吃 | 該菜的主要維度 − |
| 按「不想要」：太麻煩／沒時間 | 不改口味，降低平常的難易度範圍或「時間」面向 |
| 手邊常有的食材與醬料 | 對應食材與調味系統 ＋（很小） |

**規則**

- **明確的優先**：使用者在口味探索或口味地圖中親口說的，隱含學習不會悄悄推翻。
- **不一致時問一句，而且很少問**：例如最近記錄了好幾道辣的菜，但辣度設定很低，最多每個月在首頁問一次：「你最近記錄了好幾道辣的菜，要把辣度調高嗎？」
- **慢慢淡化**：隱含的訊號會隨時間慢慢變輕（例如一年後剩一半），讓口味可以隨季節與生活改變。
- **資料不足就不裝懂**：把握程度不夠的維度，點子不用它來加分，也不在口味名片上顯示。

## 七、怎麼用在點子上

1. **硬限制先篩**：過敏、宗教與文化、飲食原則、當天的週期性規則（例如今天是農曆十五）。
2. **喜好算分**：候選菜和使用者偏好的相似度，只計算把握程度夠的維度。
3. **情境調整**：依下廚頻率與願意花的時間限制難易度；依挑戰意願決定「新挑戰」跳多遠。
4. **送給 AI 的摘要**：只送結果，不送原始回答。宗教與文化轉成具體的排除清單（「不含豬肉、不用米酒」），不送宗教標籤。

**資料不足時**：新手只做了幾題、把握程度都不夠時，大廚不硬給點子，而是誠實地說「再告訴我一點你的口味，或記錄幾道你做的菜，我就能給你更準的點子」（見 [12 第五節](12-onboarding.md)）。

## 八、資料

| 資料 | 說明 |
|------|------|
| `PreferenceDimension`（字典） | 所有維度的定義：代碼、群組、名稱、上層維度（樹狀）、說明例子。隨版本發佈 |
| `QuizItem`（字典） | 題庫：題型、文字、適用地區、維度對應、後續題目、需要排除的硬限制 |
| `PreferenceProfile`（使用者） | 每個維度的喜好程度、把握程度、來源（你設定的／探索回答／行為學習）、更新時間；情境；最後一次探索的時間 |
| `DietaryProfile`（使用者，既有） | 硬限制：過敏、不吃的食物、飲食原則、宗教與文化規則、週期性規則 |

食譜（自己的與朋友的）、內建家常菜都用同一套維度標註（由字典與 AI 依文字補的標籤），推薦時才能直接比對。

**隱私**：`PreferenceProfile` 和 `DietaryProfile` 預設只有本人能讀；`DietaryProfile` 只有在使用者同意時才給同廚房的家人讀（見 [05](05-data-model.md)）。宗教與文化的選項永遠不會出現在個人料理頁。
