## 一頁摘要

**一句話**：朋友之間的料理社群，加上一位懂你的靈感大廚。

**核心循環**：打開首頁看看朋友最近做了什麼 → 喜歡的收藏起來、想煮時問大廚要點子 → 做出值得記住的就記錄一篇 → 朋友按反應、留言、照著做。
不期待每天使用；一個月打開兩次的人，和每天打開的人，體驗一樣好。

**六個關鍵設計判斷**

1. **朋友是最好的靈感**：首頁是朋友的動態與互動，加上大廚的點子。只有朋友，沒有陌生人與熱門推薦。
2. **記錄像發一篇貼文**：自己寫的內容只有「食譜」一種，是精選的、值得記住的料理，有照片、故事和心得，做法想寫再寫；不追求完整，漏記也沒關係。不顯示任何頻率或連續天數。
3. **口味地圖**：不用圖片，用描述性的菜卡、二選一、口味光譜、快問快答自適應地了解口味；過敏與宗教文化是硬限制。資料不夠時大廚不硬給點子。
4. **食材只問有沒有**：食材清單是靈感素材庫，不記數量、不追蹤用量；有效期限是選填的，設了才會提醒。
5. **雲端為唯一的資料來源**：資料都在 Supabase，換手機、家人共用都自然成立；廚房通常有好網路，所以不做離線（決策 46）。
6. **以「廚房」為單位**：食材和廚具屬於廚房，食譜、口味、帳號屬於個人。家人用邀請連結直接加入同一個廚房、共用食材。

**建議技術組合**（細節見 [04](04-architecture.md)）

```
前端    Vite + React + TypeScript + vite-plugin-pwa（Workbox）
資料    TanStack Query＋supabase-js（不做離線）
後端    Supabase（Postgres / Auth / Storage / Realtime / Edge Functions）
AI     Claude API（只經後端代理呼叫）
```
