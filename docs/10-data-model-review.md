# 10 資料模型檢視（紀錄）

**檢視日期**：2026-11-18
**檢視對象**：[05 資料模型](05-data-model.md)，以及 [04 技術架構](04-architecture.md) 中和資料有關的決策（ADR-02、03、16、17）
**檢視原則**：正規化（沒有重複資料）、可擴充性、存取效率、使用彈性

> 這份是檢視紀錄。M0 前的項目都已套用到 05、04；這裡只留每一項的結論，以及**還沒套用、要在對應階段前處理的項目**。之後資料模型以 [05](05-data-model.md) 為準。

## 結論

骨架是對的：全站字典獨立、廚房與個人的切分、食材用事件記錄、ID 在手機產生（UUID v7）、存原始值與原始單位、雲端專用資料不放手機。檢視找到 22 處要調整，其中 3 處（D1–D3）會造成資料錯誤或功能做不出來，已在 M0 前改好。

## 已套用

| # | 問題 | 改了什麼 |
|---|------|---------|
| D1 | 同步用「上次同步時間」拉取會漏資料 | 曾新增伺服器序號與混合邏輯時鐘；**決策 46 不做離線後已不需要**，相關欄位都拿掉 |
| D2 | 家人共用的廚具，出場次數算不出來 | **已撤銷**（決策 35：不記廚具使用次數） |
| D3 | 過敏原和其他私人設定放在一起 | 新增 `DietaryProfile`，使用者與家人檔案共用 |
| D4 | 暱稱存在兩個地方 | 新增 `UserIdentity`，暱稱與頭像只存這裡 |
| D5 | 照片的關聯存了兩個方向 | 照片只記錄自己屬於誰，加上排序與封面 |
| D6 | 「照哪份食譜做」有兩個欄位 | 只留 `recipeId` |
| D10 | 快取值沒有統一規則 | 05 新增「衍生欄位」表；季節改為查詢時計算 |
| D11 | 「一起吃的人」分散在四個欄位 | 合併成一個 `Diner` 清單 |
| D12 | 食譜步驟沒有 ID | 步驟與食材項目加上穩定 ID |
| D13 | 過敏原、飲食限制寫死 | 改成字典資料 |
| D14 | 日期與時區沒有定義 | 新增 `Instant`、`LocalDate`；`Kitchen` 加時區與地區（決策 17、18） |
| D18 | 「冰箱能做的食譜」沒有索引 | 食譜新增衍生欄位 `ingredientIds` |
| D19 | 索引缺少組合查詢 | 補上組合索引；決策 46 後改寫成 Postgres 索引（見 05） |
| D22 | 推薦回饋只存在手機 | 新增雲端的 `ProductEvent`（決策 23）；決策 47 擴大成通用的產品事件（見 14） |
| D7 | 每人次數和方案設定各存一份 | 決策 44 取消每日次數；`Entitlement` 只留選填的 `fairUseOverride`，平常以系統設定為準 |
| D16 | 反應、留言用 `{type, id}` 指向食譜或收藏 | 決策 43 把料理收藏併入食譜後，只剩食譜一種對象，改成直接的 `recipeId` 外鍵 |
| 其他 | `KitchenMember` 缺 ID 與修改時間、`RecipeSnapshot` 未定義、分享來源只存名字 | 已補上 |

願景調整後另外移除：食材的數量欄位與相關事件類型（只記有沒有）、`EquipmentUsageEvent`；`CookLog` 改名為 `DishPost`（料理收藏），之後再由決策 43 併入 `Recipe`。
