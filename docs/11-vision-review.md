## 一、轉向：從「料理管家」到「靈感夥伴＋料理收藏」

| 原則 | 意思 | 轉向前的規格 |
|------|------|-------------|
| **靈感優先，記錄其次** | 核心是「想煮的時候給點子」，記錄是為了留住值得記住的料理 | 以「每天記錄 → 分析習慣 → 推薦」為核心，日誌是「最重要的資料」 |
| **偶爾用也完整** | 一個月打開兩次的人和每天打開的人，體驗一樣好；不出現讓人覺得「落後」的數字 | 本月下廚次數、連續天數、週報、浪費報告、日曆、每日到期推播 |
| **食材只問有沒有** | 食材清單是靈感素材，不是庫存帳 | 精確與模糊數量、五級到期提醒、自動扣減、丟棄原因、購物清單 |

收藏像 Instagram 的**貼文**（精心挑照片、寫心得），不是限時動態（快速、頻繁）。

```
轉向前：每天記錄 → 系統分析習慣 → 每天推薦 → 每天提醒到期 → 每週回顧
轉向後：想煮的時候打開 → 看朋友做了什麼、大廚的點子 → 煮了值得記住的就記錄一篇（決策 43 起叫「記錄」） → 朋友按反應、收藏食譜
```

## 二、七個決定

| # | 問題 | 最後的決定 | 決策 |
|---|------|-----------|------|
| Q1 | 食材的期限與到期提醒 | 期限保留為**選填、放在次要層級**；設了期限的才提醒，並告訴使用者「設定期限會提醒你」。另加「最近買的」「想先用掉」兩個輕量訊號；不做系統估算、浪費統計 | 29 |
| Q2 | 購物清單 | **不做**。食譜頁顯示「你缺這幾樣」，可複製或分享到常用的待辦、提醒 App | 30 |
| Q3 | 「料理日誌」的名稱 | **「料理收藏」**：值得記住的料理，鼓勵加上「值得記住的原因」標籤 | 31 |
| Q4 | 首頁 | 原「今天」改為「靈感」，不放任何待處理的事；後由決策 36 改為「首頁」，加入朋友的動態與互動 | 32、36 |
| Q5 | 回顧與洞察 | 拿掉所有頻率類統計，改為**「收藏冊」**，保留季節、年度等較長時間的回顧 | 33 |
| Q6 | 口味冷啟動 | 新手口味探索＋多來源口味檔案；後由決策 41 改為不用圖片的「口味地圖」 | 34、41 |
| Q7 | 廚具出場次數與復活計畫 | **不記次數**，改為正向的廚具靈感；傳家寶、故事、拿手菜保留 | 35 |

## 三、因此移除的東西

下廚次數與連續天數、週報、浪費報告、營養餐盤、調味習慣統計、日曆、每日推薦與每日到期推播、食材數量與自動扣減、丟棄原因、保存天數估算、購物清單與「我去買」、廚具出場次數與冷落天數、資料模型的 `EquipmentUsageEvent`。
